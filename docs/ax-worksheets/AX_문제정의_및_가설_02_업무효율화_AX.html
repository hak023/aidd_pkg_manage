개선 대상 업무와 문제

분석 기준

지능망 서비스 개발 BA 담당자가 요청사항을 접수하고 현황·연동 조건을 확인한 뒤, 개발 범위를 판단하여 PRD·Architecture 초안과 개발계획서를 작성·공유하고 협력사 제공 Architecture·QA 문서를 검토하는 업무. 이번 문제분석은 요청·협의 내용을 문서로 정리하고 수신자별로 전달하는 과정에 집중함. 후속 Testbed 시험과 상용 적용은 문서의 활용 맥락이며, 시험 수행 자체의 자동화는 별도 업무로 구분함.
개발 산출물 작성
PO부서·운영부서·고객영업·VoC처리부서 등의 요청을 받으면 개발 BA 담당자가 User Story, Outlook·Teams의 회의·질의 내용, 연동부서의 시스템 처리 정보를 확인함. 개발 필요성과 범위를 판단한 뒤 PRD·Architecture 초안·개발계획서로 정리하고 협력사와 유관부서에 전달하는 과정에서, 같은 개발사항을 상대별로 다시 작성하고 필요한 부분을 반복 설명함. 협력사에서 상세 Architecture와 QA 문서를 제공하면 요청사항과 설계·시험 항목이 연결되는지도 검토해야 하므로, 초기 협의 내용을 후속 문서 검토까지 이어서 활용할 필요가 있음.
사용자가 보고한 영향: 협력사에 개발 의도를 전달하기 위한 추가 설명과 유관부서별 전달자료 재작성이 반복되어 담당자의 문서 작성·협업 부담이 발생함. 잠재 영향: 전달 내용의 해석 차이나 누락이 남으면 설계 협의와 QA 검토에서 추가 확인이 필요할 수 있음. 실제 설계 지연·QA 누락·서비스 장애가 발생했다는 근거는 제공되지 않음. 문서 작성·재설명에 소요된 시간, 문제 발생 건수 및 재작업 횟수는 미측정이며 개선 여력도 아직 정량화하지 않음.
현재 대응: 담당자가 Outlook·Teams 자료를 검토하여 개발 필요성·범위를 판단하고 PRD·Architecture 초안을 작성함. 협력사에 추가 설명하며, 유관부서별 공유 내용을 별도로 정리함. 협력사의 상세 Architecture·QA 문서는 담당자가 검토함. 유지할 조건: 고객 필요성·최소 개발 범위·연동 조건의 판단, 협력사와의 설계 및 FP 협의, QA 항목 검토와 실제 시험·검증을 유지함. 상용 적용 후 영향도·VoC 확인도 대체하지 않음. 문서마다 목적과 수신자가 다르므로 단순 복사만으로 처리하지 않으며, PO부서·운영부서 등 필요한 대상에 결과를 공유하는 역할을 유지함.

사실·근거와 확인사항

업무분석 2번: 개발 업무는 상시 발생하며 월평균 약 5건이라고 작성되어 있음. 이는 전체 개발 업무량에 대한 경험치이지 반복 작성 문제의 발생 건수는 아님. 업무분석 3번: Outlook·Teams 확인, PRD·사업개발계획서 작성, Architecture·QA 문서 검토의 흐름과 인계·대기 지점이 기재되어 있음. 업무분석 4번: 협력사에 필요한 부분을 계속 설명하고, 유관부서 및 개발부서 협력 시 내용을 다시 작성하여 전달한 경험이 기재되어 있음. 원문의 근거 수준은 '경험에 따른 추정'임. 확인 가능한 자료로 요청·연동사항·협의 내용의 메일·Teams 이력이 제시되어 있으나, 이번 작성에서는 해당 원본 기록과 산출물을 직접 열람·대조하지 않았음. 아래 확인 수준은 사용자가 보고한 경험을 기준으로 선택함.
직접 경험·관찰
원인 가설 1: 요청·회의·현황조사 내용이 여러 대화와 자료에 나뉘어 있고, 이를 요구사항·연동 조건·결정사항·미확인사항으로 정리하는 작업이 담당자에게 집중되어 문서 작성 때마다 재해석이 발생할 수 있음. 원인 가설 2: 동일 요구사항을 PRD, Architecture 초안, 개발계획서, 공유자료와 QA 검토에 재사용하는 방식이 충분히 정리되지 않아 수신자별 재작성과 문서 간 대조가 반복될 수 있음. 원인 가설 3: 상황별 판단과 기술적 맥락이 전달자료에 충분히 표현되지 않으면 협력사의 추가 질문과 재설명이 발생할 수 있음. 이는 반복 작성 경험과 사용자가 기재한 원인을 바탕으로 한 가설임. 기존 공통 양식·정보 재사용 방식의 유무와 실제 재설명 원인은 확인이 필요함.
최근 개발 건에서 반복이 집중되는 구간과 원인: 원자료 부족, 요구사항 변경, 전달 누락, 해석 차이를 구분해야 함. 공통으로 재사용 가능한 요구사항과 문서별 별도 판단 항목, 기존 문서 양식·작성 기준·버전 관리 방식을 확인해야 함. 건별 자료 정리·문서 작성·검토·재설명 시간, 회신 대기시간, 재작업 횟수, 실제 요구사항 누락 여부는 미측정임. 메일·회의자료·시스템 정보의 사용 권한, 민감정보 처리 기준, 허용 AI 환경 및 외부 서비스 전송 가능 여부는 확인 필요함. Outlook·Teams 직접 연동 가능 여부도 확인되지 않음.
지능망 서비스 개발 BA 담당자는 요청·협의 내용을 개발 산출물로 작성하고 협력사·유관부서에 전달하는 과정에서 같은 내용을 수신자별로 다시 정리하고 반복 설명해야 하므로 문서 작성과 협업 부담을 겪고 있다.
02

AX 적용 컨셉과 가설

기준 문제개발 산출물 작성
출처 기반 개발 산출물 작성 지원 에이전트 (AI 제안)
직접 이용자: 개발 BA 담당자. 요청 접수·회의 후 요구사항을 정리할 때, PRD·Architecture 초안을 작성할 때, 협력사·유관부서 공유자료를 준비하거나 후속 문서를 검토할 때 사용함. 결과 활용자: 개발협력사, PO부서, 운영부서 및 필요 시 요청부서. 담당자가 검토·확정한 문서와 공유자료를 전달받으며, 이들이 AI 도구에 직접 접속하는 것은 이번 컨셉의 전제로 두지 않음. 문제를 겪는 주체와 도구의 직접 이용자는 개발 BA 담당자이며, 협업 상대는 명확한 전달자료의 수혜자로 구분함.
업무의 변경 방향
담당자가 메일·Teams의 요청과 회의내용, 현황·연동 정보를 확인하고 상황에 맞게 개발 범위를 판단함. 이를 PRD·Architecture 초안과 개발계획서로 작성하여 전달함. 협력사가 이해하지 못한 부분은 추가 설명하고, 유관부서별로 필요한 내용을 다시 작성함. 상세 Architecture·QA 문서가 오면 요구사항과 비교하여 검토함. 기존 문서 양식과 정보 재사용 체계의 구체적인 운영 방식은 미확인임.
개선안: 담당자가 사용 권한이 확인된 요청·회의·현황자료를 개발 건별로 제공하고, AI가 요구사항·연동 조건·결정사항·미확인사항을 출처와 함께 추출·정리함. 상충하거나 근거가 부족한 내용은 임의 확정하지 않고 확인 질문으로 제시함. 담당자가 개발 범위와 정리 내용을 검토·수정한 뒤, AI가 검토된 정보를 바탕으로 PRD 초안과 수신자별 공유자료를 작성함. 같은 정보를 Architecture 초안·개발계획서의 관련 내용 작성에도 재사용하도록 지원함. 협력사 문서가 제공되면 요구사항 대비 불일치·누락 가능성과 QA 확인 항목을 제안하고, 담당자가 근거를 확인하여 최종 판단함. 검토 전 초안을 자동 발송하거나 업무 시스템에 반영하지 않음. 초기에는 담당자가 자료를 직접 제공하는 방식을 가정하며 직접 연동은 별도 검토함.
기대 가설: 자료 재정리와 수신자별 문서 재작성에 드는 직접 작업시간을 줄이고, 개발 의도 전달 부족에 따른 반복 설명을 줄일 수 있음. 기대 가설: 동일한 검토 정보를 재사용하고 출처·미확인사항을 함께 제시하면 문서 간 내용 대조와 요구사항 확인을 수월하게 할 수 있음. 현재값과 개선 실적은 없으며 절감률을 확정하지 않음. AI 초안의 오류를 수정하고 출처를 확인하는 시간까지 포함하여 순효과를 판단해야 함. 협력사 개발 완료나 외부 회신 대기가 자동으로 단축된다고 가정하지 않음.
AI 적용 이유: 회의·메일의 비정형 표현을 맥락에 맞게 요약·분류하고, 여러 자료의 요구사항과 상충 내용을 비교하며, 같은 사실을 문서 목적과 수신자에 맞춰 초안으로 표현하는 작업을 지원할 수 있음. 정확성은 실제 자료로 검증해야 함. 일반 자동화 영역: 개발 건별 자료 묶기, 정해진 양식에 값 넣기, 문서 저장·버전 기록은 규칙 기반 처리로 구현할 수 있음. 업무 절차 개선 영역: 공통 요구사항 항목, 문서별 작성 기준, 검토·공유 시점을 먼저 정리해야 함. 양식 표준화와 정보 재사용만으로 해결되는 부분은 AI 성과와 구분함. 사람의 영역: 개발 필요성·타당성·범위 결정, 설계 확정, FP 협의와 시험 결과 판단은 AI에 위임하지 않음.
제안 범위: '개발 프로세스 진행' 중 사용 가능한 요청·회의·현황자료의 출처 기반 정리, 담당자 검토, PRD 초안 및 수신자별 공유자료 작성·수정 지원. 연결 범위: 검토한 요구사항을 Architecture 초안·개발계획서의 관련 내용에 재사용하고, 제공된 상세 Architecture·QA 문서와 대조하여 확인할 항목을 제안함. 핵심 효과 확인은 PRD와 공유자료 작성에 우선 집중하며, 연결 문서별 실제 지원 수준은 후속 구조정의에서 검토함.
개발 타당성·최소 개발 범위·최종 설계·FP·투자심의의 자동 결정 또는 승인. 협력사 코딩, Testbed 환경 구성과 실제 테스트 실행의 자동화, 상용 PKG 적용 및 운영 조치. 검토 전 문서 자동 발송, 투자심의 ERP 등 실제 업무 시스템에 대한 자동 입력·변경. 사용 권한이 확인되지 않은 자료의 수집·외부 전송, Outlook·Teams의 무조건적인 자동 수집·상시 연동. 별도 업무인 '개발사항 테스트'와 '요청사항 공유' 전체의 자동화.
개발 BA 담당자에게 요청·협의 자료를 출처와 함께 정리하고 검토된 요구사항을 개발 문서와 수신자별 공유자료에 재사용하는 AI 작성 지원을 제공하여, 최종 판단과 검증 책임을 유지하면서 반복 작성·재설명 부담을 줄이고자 한다.
핵심 가설: 사용 가능한 요청·협의 자료를 AI가 출처와 함께 구조화하고, 담당자가 검토한 요구사항을 PRD와 수신자별 공유자료에 재사용하면, 같은 정보를 반복 해석·작성하는 작업이 줄어 담당자의 총 직접 작업시간과 전달 불충분에 따른 재설명이 감소할 것이다. 검증 제안: 동일한 자료·문서 범위를 사용한 기존 작성 방식과 AI 지원 방식을 비교하고, 자료 준비·작성·검토·수정에 실제 투입한 시간을 모두 포함한다. 가능한 경우 양식 표준화·재사용만 적용한 방식도 비교하여 AI의 추가 기여를 구분한다. 품질 조건: 출처 없는 내용, 요구사항 누락, 문서 간 불일치가 기존 방식보다 증가하지 않아야 한다. 담당자와 협업 상대의 내용 검토로 확인하며, 요구사항 자체의 변경에 따른 수정은 전달 불충분에 따른 재작업과 분리한다. 반증 조건: AI 초안의 출처 확인·수정 부담으로 총 직접 작업시간이 줄지 않거나 품질 오류가 증가하면 가설을 지지하지 않는 것으로 본다. 현재값·목표 수치·표본 규모는 미정이며 비교 검증은 미실시임. 구체적인 측정 기준은 후속 구조정의에서 검토한다.
자료 사용 조건: 필요한 메일·회의·현황자료를 적법한 권한으로 확보할 수 있고, 민감정보 처리를 포함하여 사용할 AI 환경이 조직 기준에 부합해야 함. 현재 권한과 허용 환경은 미확인임. 입력 품질: 자료에 개발 의도·연동 조건을 판단할 정보가 포함되어야 하며, 빠진 정보는 관계자에게 확인할 수 있어야 함. AI가 원자료에 없는 사실을 보완한다고 가정하지 않음. 업무 조건: 문서별 작성 기준과 공통 요구사항 항목을 정리할 수 있고, 담당자가 출처·상충 내용·초안을 검토할 시간을 확보해야 함. 기술 조건: 한국어 업무·통신 기술 용어를 다루는 추출·비교·초안 품질이 검토 가능한 수준이어야 하며, 원자료와 결과의 출처 연결이 유지되어야 함. 실제 성능은 미검증임. 검증 조건: 비교 대상의 범위·난이도·문서 품질 기준을 맞추고, AI 검토·수정 비용과 일반 자동화의 효과를 분리하여 측정할 수 있어야 함.
