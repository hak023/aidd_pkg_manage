01

핵심서비스 개념과 제작 의도

출처 기반 개발 산출물 작성 지원
개발 BA 담당자가 요청·회의·연동 메모를 정리하고 PRD와 협력사·PO·운영부서 공유자료를 준비하는 상황. 이번 사용자는 로컬 단일 사용자이며 로그인·다중 사용자 동시 편집은 없음.
같은 요청을 반복 해석하고 수신자별 문서를 다시 쓰는 부담을 줄이는 사용 흐름을 확인함. 출처 확인·사람 검토·버전 변경을 드러내어 잘못된 문서가 확정되는 것을 방지하는 안임. 실제 시간 절감이나 AI 품질 개선은 이번 시연으로 입증하지 않음.
합성 개발 건 '통화 이력 조회 조건 개선'으로 자료 준비→요구사항·출처 검토→PRD·공유자료 검토의 3개 화면을 시연함. 정상·미검토·상충·자료 사용 미확인·생성 오류·복원·원문 변경·요구사항 변경의 8개 시나리오를 선택하고 준비된 단계와 결과를 체험함. 원문·문서 탭·검토 선택·차단 사유·변경 전후는 실제 화면에서 작동함. 자료·요구사항·문서의 편집 적용, 변경 전파, 확정 조건 판정, 작업 JSON 저장·복원은 합성 데이터 범위에서 실제로 동작함. 의미 추출·초안 생성은 고정 샘플이며 조직 승인·AI 분석이 아님. 문서 확정 표시는 시연 상태이며 정식 승인·실제 발송·AI 분석 결과가 아님.
F-01 PRD·공유자료 작성 지원을 중심으로 F-04 자료·출처 관리, F-05 검토·버전 통제, F-06 파일 저장·복원을 포함함. 담당자 검토를 생략하지 않고 동일 요구사항의 재사용과 문서 간 근거 연결을 확인함.
'통화 이력 조회 조건 개선'이라는 합성 개발 요청을 사용함. 담당자가 날짜 검색·조건 초기화·기존 조회 연동 유지 요구를 확인하고, PRD와 협력사·PO·운영부서 요약을 검토한 뒤 작업 파일을 저장·복원하는 장면. 실제 KT 서비스 요구사항이나 확정 개발 건이 아님.
교육생 직접 보완 전 AI 제안: 생성 속도보다 원문 확인, 문서 간 동일 요구사항 유지, 오류 시 보류, 검토본 복원을 강조함. 교육생이 확정한 화면 취향·세부 업무 규칙으로 간주하지 않으며 제작 요청본 전환 전에 보완할 항목임.

요구사항·문서 편집, 출처 이동, 문서 종류 전환, 수정 기록 표시. PRD는 배경·포함 범위·제외 범위·요구사항·확인사항, 공유자료는 상대별 전달 내용·확인 요청으로 구성함. 초안에는 해당 시점의 요구사항 ID·버전과 입력 집합 버전을 연결함. 이 연결은 규칙 기반이며 AI 생성으로 표시하지 않음. 문서 생성·재생성은 명시적 요청과 기존 편집본 교체 동의가 있어야 하며, 취소 시 내용·상태·버전 모두 유지함.
의미 추출과 자연어 초안은 명시적으로 선택한 고정 샘플. 샘플 초안 적용은 원자료뿐 아니라 전체 요구사항의 집합·내용·포함/제외 분류·출처가 기준 샘플과 일치하고 모든 대상 항목의 검토가 완료된 경우만 허용함. 검토자·시점은 일치 비교에서 제외하고 최신 검토 여부를 따로 검사함. 원자료가 같아도 요구사항만 수정·추가·제외하면 예전 샘플 초안 적용을 차단함. 변경을 자동 해석·재작성하지 않고 기존 본문을 보존한 채 수동 작성으로 전환함. 기준 내용으로 되돌려도 버전과 검토 기록은 자동 복구하지 않으며 새 검토 후에만 샘플 적용 가능. 변경 영향 제안: 준비된 한 가지 변경(조회 조건 초기화를 '한 번에'에서 '항목별'로 바꾼 요구사항)에 한해 4개 문서의 해당 문장을 고정 규칙으로 바꾼 제안과 변경 전후를 보여 줌. 제안은 사람이 문서별로 적용해야 하며 적용 후에도 재검토 상태임. 그 외 변경은 제안 없이 수동 수정.

정상 합성 요청의 요구사항 4개와 문서 4종을 모두 검토 확정한 작업. 검토자 '시연 담당자'. 모든 자료는 v1이며 문서의 초기화 표현은 '일괄'이거나 표현 없음.
조회 개선 요청 2행을 '조회 조건을 항목별로 초기화할 수 있어야 한다.'로 변경하고 요구사항 '조건 초기화'도 같은 문장으로 수정함. 준비된 변경 영향 제안은 이 한 가지 변경에만 제공함. 다른 문구로 바꾼 요구사항은 제안 없이 수동 수정함.
1. 자료 준비에서 조회 개선 요청 2행을 수정 적용하고 생성된 4개 문서가 모두 재검토로 바뀐 것을 확인함. 2. 요구사항 검토에서 영향받은 '날짜 조건 검색'과 '조건 초기화'의 출처를 갱신하고('조건 초기화'는 내용도 수정) 수정 적용 후 원문과 대조해 검토 완료함. 3. 문서 검토의 문서 간 정합성 표에서 문서 4개의 핵심 내용과 초기화 표현이 요구사항과 같은지 확인함. 4. 변경 영향 제안에서 PRD만 적용하고 정합성 표와 확정 조건을 확인함. 문서 간 표현이 달라 확정이 차단되는지 확인함. 5. 나머지 3개 문서에 제안을 적용하고 각 문서의 근거 반영 확인·검토 확정을 수행함. 6. 다른 문구로 요구사항을 바꾼 별도 작업에서는 제안이 제공되지 않고 수동 수정만 가능한지 확인함.
변경 영향 제안은 문서별 변경 전후 문장을 보여 주되 자동 적용·자동 확정하지 않음. 일부 문서만 갱신하면 '문서 간 표현 불일치'로 해당 문서의 확정이 차단되고, 4개 모두 갱신·검토한 뒤에만 확정됨. 준비되지 않은 변경에는 제안을 만들지 않음. 이 장면은 재작성 대상 문서 수와 수동 수정 횟수를 확인하는 시연이며 시간 절감을 입증하지 않음.

S-03 · PRD·공유자료 검토 및 저장
정상 합성 요청의 문서 4종을 모두 검토 확정한 작업. 검토자 '시연 담당자'.
합성 질문 3건. 협력사: '초기화가 조회 결과 목록까지 포함하는지 알려 주세요.' PO: '조회 기간 상한을 7일로 제한할 수 있나요?' 운영: '엑셀 내보내기는 언제 개발하나요?' 모의 분류 제안은 각각 전달 불충분, 요구사항 변경, 범위 밖임.
1. 문서 검토에서 질문 3건을 접수하고 모의 분류 제안을 확인함. 2. 협력사 질문을 '전달 불충분'으로 분류하고 협력사 문서가 재검토로 바뀌는지, 문서 수정 전 확정이 차단되는지 확인함. 3. PO 질문을 '요구사항 변경'으로 분류하고 문서·요구사항이 자동으로 바뀌지 않는지 확인함. 4. 운영 질문을 '범위 밖'으로 분류하고 담당자 답변 필요로 남는지 확인함. 5. 협력사 문서에 '조회 결과 목록의 초기화 여부는 이 자료로 확인되지 않음'이라는 미확인 문구를 추가하고 근거 반영 확인·검토 확정함. 6. 질문 분류별 건수가 재설명 집계와 변경 요청으로 나뉘어 표시되는지 확인함.
전달 불충분 질문만 문서 보완과 재검토를 요구하고 문서를 수정하면 질문이 보완 완료로 바뀜. 요구사항 변경 질문은 재설명으로 집계하지 않고 변경 요청으로 분리하며 요구사항을 바꾸기 전에는 문서를 바꾸지 않음. 범위 밖 질문은 사실을 지어내지 않고 담당자 답변 대기로 남음. 분류는 사람이 확정하며 모의 제안은 참고용임. K-04 재설명 횟수의 실제 개선은 업무 시범 적용에서 측정함.
