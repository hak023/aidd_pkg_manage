개발 BA 담당자가 요청·협의 내용을 개발 산출물로 작성하고 협력사·유관부서에 전달할 때, 같은 내용을 수신자별로 재정리하고 반복 설명하여 문서 작성·협업 부담을 겪음. 실제 작업시간과 오류 발생률은 미측정임.
출처 기반 개발 산출물 작성 지원 에이전트. 요청·협의 자료를 출처와 함께 정리하고, 담당자가 검토한 요구사항을 PRD·공유자료와 관련 개발 문서에 재사용함. 개발 판단·문서 확정·실제 시험은 사람이 수행함.
출처와 연결된 요구사항을 구조화하고 담당자 검토 후 문서에 재사용하면 반복 해석·작성과 전달 불충분에 따른 재설명이 감소할 것이라는 가설. 자료 준비·작성·검토·수정 시간을 모두 포함하여 비교하며, 출처 없는 내용·요구사항 누락·문서 간 불일치가 증가하지 않아야 함. 검토·수정 부담 때문에 총 작업시간이 줄지 않거나 품질이 악화되면 가설을 지지하지 않음. 일반 양식 표준화·재사용의 효과와 AI의 추가 기여를 구분함.
03

AI 적용 지점과 핵심 기능

3개 기능
F-01출처 기반 PRD·수신자별 공유자료 작성 지원프로토타입 핵심
출처 기반 PRD·수신자별 공유자료 작성 지원
요청 접수·현황 확인 후 요구사항 정리, PRD 초안 작성 및 협력사·유관부서 인계 준비
요청·회의·현황자료에서 요구사항, 연동 조건, 결정사항, 미확인사항을 출처와 함께 추출함. 상충 내용은 확인 질문으로 제시함. 담당자가 검토·수정한 요구사항을 기준으로 PRD 초안과 협력사·PO부서·운영부서용 공유자료 초안을 작성함. 출처 없는 설명은 사실로 보완하지 않음. 자료 묶기·문서 양식 적용·버전 기록은 규칙 기반 처리이고, 의미 추출·요약·수신자별 표현은 AI 지원 영역임.
담당자가 사용 권한을 확인하여 제공한 User Story, 메일·Teams 회의·협의 내용, 현황·연동 정보, 적용할 PRD 양식. 개발 건 식별정보, 자료 제목·작성일·버전·원문 위치를 함께 유지함. 초기에는 텍스트 직접 입력·제공을 가정하며 자동 수집은 하지 않음. 원자료 변경 시 변경된 부분과 영향 문서를 추적함.
실제 메일·회의 원본과 PRD 양식은 미제공이며 사용 권한, 보안 처리, 허용 AI 환경은 미확인임. 확인 전에는 합성 자료만 사용함. 실자료를 입력하기 전에 자료별 사용 가능 범위·수신 대상·보존 조건을 확인해야 함.
확인 필요
출처·원문 발췌·검토 상태가 연결된 요구사항 목록, 미확인·상충 질문, PRD 및 수신자별 공유자료 초안. 최종 검토 후 문서 버전, 근거 자료 버전, 검토자·검토 시점 및 수정 내역이 연결된 내보내기 결과. 검토용 파일에는 초안·보류 표시를 유지함.
개발 BA 담당자가 요구사항·개발 범위와 문서 내용을 검토·수정함. 확정한 문서는 기존 전달 절차로 협력사와 PO·운영부서 등에 공유함. AI는 전송하지 않음. 검토 요구사항은 F-02·F-03의 기준 입력으로 재사용함.
사용 가능한 자료 안에서 추출·정리·초안 생성만 자동 수행함. 담당자가 요구사항을 검토하기 전에는 확정 문서로 전환하지 않음. 미확인사항을 포함한 검토용 초안 저장은 허용하되, 배포용 확정은 대상 범위의 미해결 쟁점·품질 오류가 없고 담당자 확인이 기록된 경우로 제한하는 안임. 개발 타당성·범위·설계·FP·투자심의 승인과 실제 발송은 자동화하지 않음.
사람 확인 후 반영
공통 요구사항 항목과 문서별 작성 기준, 개발 건·버전 구분, 담당자 검토 절차가 필요함. 자료의 접근·보존 정책과 AI 사용 환경은 별도 확인함. PRD 초안 품질과 검토 부담 감소는 아직 미검증임. UI의 '확정' 표시는 문서 검토 상태이며 조직의 정식 사업·투자 승인을 의미하지 않음.
F-02검토 요구사항의 관련 문서 재사용 지원
검토 요구사항의 관련 문서 재사용 지원
Architecture 초안·개발계획서의 관련 내용 작성
F-01에서 검토한 요구사항과 결정사항을 문서 목적에 맞게 재구성하여 Architecture 초안의 기능·연동 설명과 개발계획서의 배경·범위 초안을 제안함. 문서 간 동일 요구사항과 출처·버전을 연결함.
검토 요구사항 버전, 담당자가 결정한 개발 범위, 확인된 현황·연동 조건, 문서별 양식. FP·일정·비용은 사람이 제공한 값만 참조하고 없는 값은 미확인으로 남김.
실제 문서 양식·입력 자료의 사용 조건과 재사용 가능한 항목은 미확인임. 합성 예시 외 자료는 사용 가능 여부 확인 후 제공받음.
확인 필요
출처·요구사항이 연결된 Architecture·개발계획서 부분 초안과 문서 간 변경 영향 목록. 최종 상세 설계·투자심의 승인 문서로 간주하지 않음.
개발 BA 담당자가 문서 목적과 사실을 검토하며, 상세 Architecture는 협력사와 협의하여 확정함. 개발계획서 검토·승인은 기존 조직 절차를 따름.
문서 내용 초안만 제안함. 설계·FP·비용·일정을 임의 산정·확정하거나 ERP에 등록하지 않음. 검토 요구사항이 바뀌면 이전 초안의 재검토 필요 상태를 표시함.
결과 제안
문서별 작성 기준과 담당자 검토, F-01 입력 버전 고정이 필요함. 실제 지원할 세부 문서 항목과 정식 승인 권한은 확인 필요함.
F-03요구사항 대비 Architecture·QA 문서 대조 지원
요구사항 대비 Architecture·QA 문서 대조 지원
협력사 상세 Architecture·QA 문서 검토
검토 요구사항과 제공된 설계·QA 항목을 대조하여 대응 관계, 누락·불일치 가능성, 추가 확인 질문을 제안함. 문서상 대응과 실제 개발·시험 성공을 구분함.
기준 요구사항·PRD 버전, 협력사 제공 Architecture·QA 문서와 버전·원문 위치. 자료가 제공되지 않은 항목은 비교 불가로 표시함.
협력사 원본 문서와 활용 권한은 미확인임. 양식·기술 용어·자료 최신성 확인이 필요함.
확인 필요
요구사항-설계-QA 대응표, 출처가 연결된 불일치·누락 의심 목록, 비교 불가 목록 및 추가 확인 질문. 실제 시험 결과나 검증 완료 판정은 생성하지 않음.
개발 BA 담당자가 근거를 확인하고 협력사에 질문·보완 요청함. QA 검토 결과는 실제 Testbed 시험과 운용부서 검증 준비에 사용하며 시험을 대체하지 않음.
차이·누락 의심과 검토 항목만 제안함. 자동 합격·설계 승인·상용 적용은 불가함. 문서 버전이 불명확하거나 원문을 해석할 수 없으면 해당 비교를 보류함.
결과 제안
동일 개발 범위·버전의 기준 문서와 담당자 판단이 필요함. 비교 정확도·오탐·미탐은 실제 AI 시험에서 별도 검증함.

사람의 역할·권한·책임

단계별 업무 분담

R-01요구사항 정리·PRD 및 공유자료 검토
요구사항 정리·PRD 및 공유자료 검토
F-01 · 출처 기반 PRD·수신자별 공유자료 작성 지원
출처 기반 요구사항 정리와 문서 초안·확인 질문을 제안함. 검토 상태·출처 연결·문서 버전의 기록과 확정 조건 검사는 규칙 기반 지원임.
개발 BA 담당자가 자료 사용 가능 여부, 원문 의미, 요구사항·개발 범위, 문서별 표현과 수신 대상을 확인·수정함. 부족한 정보는 협업 상대에게 확인함.
사용 가능 자료와 검토 요구사항을 기준으로 초안 작성. 출처 누락·쟁점이 있으면 확인 질문과 보류 상태 유지. 대상 범위의 쟁점 해소와 최종 문서 검토 기록 후 확정하며 이후 입력 변경은 재검토로 전환함.

관련 문서 작성 및 설계 협의

검토 요구사항을 Architecture·개발계획서 관련 내용으로 재구성하고 변경 영향을 제안함.
개발 BA 담당자가 개발 의도·범위·입력 수치를 검토하고 협력사와 상세 설계를 협의함. FP와 투자심의 판단은 기존 담당·권한 체계를 유지함.
근거·버전·문서 목적이 일치할 때 채택. 미확인 수치·설계 조건은 사실로 확정하지 않으며 해당 부분을 보류함. 문서 생성 자체는 사업·투자 승인이 아님.
R-03Architecture·QA 대조 및 확인 요청
Architecture·QA 대조 및 확인 요청
F-03 · 요구사항 대비 Architecture·QA 문서 대조 지원
요구사항별 대응 관계·의심 누락·상충 내용·비교 불가 항목을 제시함.
개발 BA 담당자가 원문을 대조해 오탐·미탐을 검토하고 협력사에 설명·보완을 요청함. 실제 시험·합격 판단은 담당자와 운용부서의 기존 검증 절차에서 수행함.
문서 버전·범위가 맞고 근거를 확인할 수 있을 때 검토 결과로 채택. 자료가 없거나 해석 불가이면 비교 완료로 처리하지 않음. 문서상 일치를 개발·시험 성공으로 표시하지 않음.
R-04문서 확정·공유 및 오류 인수
문서 확정·공유 및 오류 인수
과제 전체
검토 상태와 마지막 검토본을 표시하고 관련 변경·오류를 기록함. 실제 발송·업무 시스템 변경은 수행하지 않음.
개발 BA 담당자가 수신 대상·내용·버전을 확인해 기존 방식으로 전달하고, 오류 발견 시 활용 중단·수정·재공유 필요성을 판단함. 정식 승인·중단 권한은 조직 기준 확인 후 지정함.
미검토·보류·오류 상태는 배포용 확정 불가. 문서 확정 후 내용이 바뀌면 재검토. 잘못 공유된 결과는 영향 대상을 확인하고 기존 정정 절차로 처리함.

책임과 권한

역할 제안: 개발 BA 담당자가 전 기능의 근거·요구사항·문서를 검토함. 상세 설계·QA 내용은 협력사와 확인하고 PO·운영부서의 요청 취지는 해당 부서와 확인함.
문서 내용 검토 후 확정은 개발 BA 담당 역할로 제안함. 사업·투자·상용 적용 등 정식 승인권자는 제공 자료에서 확인되지 않았으므로 기존 조직 기준에 따라 별도 확인·지정함. AI에는 승인 권한이 없음.
개발 BA 담당자가 자신이 검토·공유한 개발 문서의 내용 확인과 협업 인계를 맡는 안임. 정식 조직상 최종 책임자와 권한 범위는 미확인으로, AI 초안으로 지정하지 않음.
내용·출처 오류는 개발 BA 담당자가 인수하고 협력사·요청부서와 확인함. 기술 장애·보안 의심은 향후 지정할 구현·운영·보안 담당에게 연결함. 담당자와 대응 절차는 확인 필요함.

F-01 · 출처 기반 PRD·수신자별 공유자료 작성 지원
요청·회의·현황자료에서 요구사항, 연동 조건, 결정사항, 미확인사항을 출처와 함께 추출함. 상충 내용은 확인 질문으로 제시함. 담당자가 검토·수정한 요구사항을 기준으로 PRD 초안과 협력사·PO부서·운영부서용 공유자료 초안을 작성함. 출처 없는 설명은 사실로 보완하지 않음. 자료 묶기·문서 양식 적용·버전 기록은 규칙 기반 처리이고, 의미 추출·요약·수신자별 표현은 AI 지원 영역임.
제안: 개발 BA 담당자가 합성 개발 요청 1건의 요청문·회의 메모·연동 확인 메모를 입력하고, 출처를 보면서 요구사항을 수정·보류한 후 PRD와 수신자별 공유자료를 검토·내보내는 장면. F-01을 프로토타입 핵심으로 선택함. F-02의 관련 문서 작성과 F-03의 Architecture·QA 대조는 연결 기능으로 구조만 정의하고, 이번 제작 포함 여부는 후속 제작 정의서에서 검토함.

G-05 · 처리 실패·부분 응답의 보류와 복구

실제 연결과 모의 구현 범위

제안 수준: 브라우저 로컬 동작형. 텍스트 입력·편집, 준비된 원문과 출처 위치 표시, 요구사항 상태 변경, 검토·확정 조건 검사, 문서 편집 및 버전 포함 JSON 저장·다시 불러오기를 실제 동작으로 구현하는 안임. 새로고침·종료 시 자동 보존하지 않고 사용자가 내보낸 파일로 복원하며, 저장하지 않은 변경에는 경고함. 브라우저 자동 저장 및 실계정 인증은 이번 범위에서 제외하는 안임. 아직 구현·시험되지 않았음.
합성 개발 요청·회의·연동 메모와 이에 대응하는 요구사항·PRD·공유자료의 준비된 샘플을 사용함. AI 응답은 고정 샘플이며 화면·내보내기 결과에 '모의 AI 응답'을 표시함. 자유 입력을 실제 AI로 분석했다고 표시하지 않음. 오류·누락·상충·중단 사례도 준비된 샘플로 시연함. 메일·Teams·ERP·상용 시스템 연결과 실제 발송은 없음. 역할·권한 표시는 시연용이며 실인증·보안 검증을 대체하지 않음.
정상 입력에서 원문·출처·초안이 연결되는지, 사람이 수정·보류·확정할 수 있는지, 미해결 쟁점·미검토 상태에서 확정이 차단되는지 확인할 예정임. 원자료 변경 후 관련 문서가 재검토 상태로 전환되는지, 저장·불러오기에서 내용·줄바꿈·연결·버전이 유지되는지 확인함. 모의 오류에서는 확정되지 않고 마지막 검토본으로 돌아갈 수 있어야 함. 검증은 제작 후 수행하며 현재는 모두 미실시임. KPI의 실제 개선 성과를 UI 샘플로 입증하지 않음.
실제 AI의 요구사항 추출·출처 정확도·문서 품질, 실자료 민감정보 처리와 자료 내 지시문에 대한 내성, 대용량 문서 처리, 실계정 권한·로그 보존은 후속 검증임. K-01 작업시간, K-02 품질, K-04 재설명은 실제 AI 시험·시범 업무 적용에서 측정함. K-03은 UI 단계에서 모의 통제 동작만 확인하고 실제 환경에서 재시험해야 함.
