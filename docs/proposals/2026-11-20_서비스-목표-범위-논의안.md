## 1. 출발점 요약

- **문제**: 개발 BA 담당자는 요청과 협의 내용을 PRD·Architecture 초안·개발계획서로 작성합니다. 이 과정에서 같은 내용을 협력사·PO·운영부서용으로 다시 쓰고 반복 설명합니다(월평균 개발 건 약 5건, 소요 시간은 미측정).
- **컨셉**: AI가 자료를 **출처와 함께** 요구사항으로 정리하고, 담당자가 검토한 요구사항을 여러 문서에 **재사용**합니다. 판단과 확정은 사람이 합니다.
- **현재까지 만든 것**: 시나리오 시연형 프로토타입 1개. 합성 사례 1건과 고정된 모의 AI 응답으로 화면 3개(S-01~03)를 시연합니다.

## 2. 목표

### D-01. 웹사이트의 성격

| 선택지 | 설명 | 장점 | 단점 |
|---|---|---|---|
| A. 업무 도구 | 실제 개발 건에 쓰는 작성 지원 도구 | 가설(K-01~K-04)을 실제로 검증할 수 있음 | 보안 확인(Q-01) 전에는 실자료를 넣을 수 없음 |
| B. 과제 소개 사이트 | 문제 → 컨셉 → 구조 → 시연을 보여 주는 사이트 | 빠르게 완성, 발표·공유에 적합 | 실제 업무 효과는 확인 불가 |
| **C. 도구 + 소개 (추천)** | 업무 도구를 만들되, 첫 화면에 과제 소개와 합성 사례 데모 모드를 둠 | 보안 확인 전에도 데모로 공유할 수 있고, 확인 후 실사용으로 이어짐 | 소개 페이지만큼 작업이 늘어남 |

### D-06. 데모용 합성 사례

| 선택지 | 설명 |
|---|---|
| A. 기존 사례 유지 | '통화 이력 조회 조건 개선' (프로토타입 데이터를 그대로 재사용) |
| **B. 기존 사례 + 도메인 사례 1건 추가 (추천)** | 실제 업무에 가까운 합성 사례를 하나 더 만듦. 예: 통화매니저 부가기능 추가 요청(연동부서 조건 포함). **실제 요구사항이 아닌 합성 자료**로 작성 |
| C. 도메인 사례로 교체 | |

도메인 사례의 소재(어떤 종류의 요청이 가장 대표적인지)는 사용자가 정해 주셔야 합니다.

### SC-01 대표 흐름 (추천안)

```
[개발 건 생성]
  └ 자료 등록: User Story / 회의 메모 / 메일 요지 / 연동 확인 메모
       (자료마다 '사용 가능' 확인 → 미확인이면 분석 대상에서 제외, G-01)
[AI 정리]
  └ 요구사항 · 연동 조건 · 결정사항 · 미확인사항 추출 (항목마다 원문 위치)
  └ 상충·근거 부족 → 확인 질문 목록
[담당자 검토]
  └ 원문과 대조하며 수정 / 보류 / 범위 제외(사유 기록) / 검토 완료
[문서 작성]
  └ PRD 초안 + 협력사용 · PO용 · 운영부서용 공유자료 초안 (같은 요구사항을 재사용)
  └ 편집 → 확정 조건 검사 → 확정(버전 기록)
[내보내기]
  └ Markdown / JSON 저장 · 다시 불러오기  (발송은 사람이 기존 방식으로)
```
