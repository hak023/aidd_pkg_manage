# 메일 연동 가이드 (P2)

Gmail 계정 하나로 회사 메일과 메일을 주고받게 설정하는 방법입니다. 실제 값(주소, 앱 비밀번호)은 환경 변수에만 넣고 저장소나 문서에는 쓰지 않습니다.

## 1. 동작 방식

```
[웹사이트] 수집 요청 메일 보내기 ── Gmail SMTP ──▶ 회사 메일(COLLECT_TO_ADDRESS)
                                                    │ Outlook에서 Copilot에게 "메일 내용 회신내용 작성해줘"
                                                    │ 결과를 검토하고 회신
[웹사이트] 메일 확인 ◀── Gmail IMAP(받은편지함) ◀──┘
   ├ 제목 태그 [AX_AIDD][DEV-xxxx] → 개발사항 매칭
   ├ (태그가 지워졌으면) 회신 헤더 → 본문 표식 순서로 매칭
   ├ 매칭 실패 → 미분류함 (사용자가 개발사항 지정)
   └ 수집 회신이면 1단계 완료, 2단계 진행중으로 변경
```

- **보내는 메일:** 자동 발송은 `COLLECT_TO_ADDRESS` 한 곳으로만 갑니다. 화면에서 받는 사람을 바꿀 수 없습니다.
- **받는 메일:** Gmail 받은편지함에서 아래 조건에 맞는 메일만 가져옵니다. 나머지(광고 등)는 건너뜁니다.
  - 제목에 `[AX_AIDD]` 태그가 있는 메일
  - 본문에 회신 양식 표식(`<<<AX_AIDD_REPLY_START …>>>`)이 있는 메일
  - 회사 주소(`COLLECT_TO_ADDRESS`)에서 온 메일 (태그 없이 전달한 개발사 문서 등)
- **처음 확인할 때**는 최근 3일 메일만 봅니다(`MAIL_LOOKBACK_DAYS`로 변경). 이후에는 마지막으로 확인한 메일 다음부터 가져옵니다.

## 2. 준비

1. **Gmail 2단계 인증과 앱 비밀번호:** Google 계정 → 보안 → 2단계 인증을 켭니다. 그다음 "앱 비밀번호"에서 16자리 비밀번호를 만듭니다.
2. **IMAP:** 지금의 Gmail은 IMAP이 항상 켜져 있어 따로 설정할 필요가 없습니다.

## 3. 로컬에서 설정 (`web/.env.local`)

`web/.env.local` 파일을 직접 만들고 아래 값을 넣습니다. 이 파일은 `.gitignore`에 들어 있어 커밋되지 않습니다.

```
SIMULATOR_MODE=false
GMAIL_ADDRESS=<시스템용 Gmail 주소>
GMAIL_APP_PASSWORD=<16자리 앱 비밀번호, 띄어쓰기는 있어도 됨>
COLLECT_TO_ADDRESS=<회사 메일 주소>
POLL_SECRET=<임의 문자열>
```

개발 서버를 다시 시작한 다음 화면 오른쪽 위의 **설정**에서 "현재 모드: Gmail 연동"으로 바뀌었는지 확인합니다.

- `.env.local`이 없거나 `SIMULATOR_MODE=true`이면 **시뮬레이터 모드**입니다. 실제로 메일을 보내지 않고 가상 메일함을 씁니다.
- 운영(배포)에서 메일 값이 빠져 있으면 "메일 설정 필요"로 표시되고, 메일을 보내거나 받을 수 없습니다.

## 4. 배포에서 설정 (Vercel)

Vercel 프로젝트 → Settings → Environment Variables에 3장의 값을 넣고 다시 배포합니다(Redeploy).

| 이름 | 필수 | 설명 |
|---|---|---|
| `GMAIL_ADDRESS`, `GMAIL_APP_PASSWORD`, `COLLECT_TO_ADDRESS` | 예 | 셋 다 있어야 Gmail 모드가 됩니다 |
| `POLL_SECRET` | 외부 크론을 쓸 때 | 메일 확인 주소 보호용 |
| `SIMULATOR_MODE` | 아니요 | `true`면 배포에서도 가상 메일함을 씁니다 (시연 연습용) |
| `MAIL_DAILY_LIMIT` | 아니요 | 최근 24시간 실제 발송 한도, 기본 30건 (R3) |
| `MAIL_LOOKBACK_DAYS` | 아니요 | 처음 확인할 때 거슬러 볼 일수, 기본 3일 |

## 5. 메일 자동 확인

| 방법 | 설명 |
|---|---|
| `메일 확인` 버튼 | 머리글의 버튼. 바로 확인합니다 |
| 화면 자동 확인 | 사이트를 열어 둔 동안 2분마다 확인합니다 |
| 외부 크론 | 사이트를 닫아 두어도 확인합니다. 아래 설정 |

**cron-job.org 설정 (무료)**
1. 가입 후 "Create cronjob"
2. URL: `https://<배포 주소>/api/mail/poll?secret=<POLL_SECRET 값>`
3. 실행 주기: 5~10분
4. 저장 후 "Test run"에서 응답이 `200`이고 `"mode":"gmail"`이 보이면 정상입니다. `401`이면 secret 값이 다릅니다.

## 6. 처음 연결했을 때 확인 순서

1. 개발사항을 하나 만들고 **수집 요청 메일 보내기**를 누릅니다. 미리보기에서 받는 사람과 본문을 확인하고 보냅니다.
2. 회사 메일에 메일이 왔는지 확인합니다. 스팸함도 확인합니다(위험 R4).
3. Outlook에서 메일을 열고 Copilot에게 "메일 내용 회신내용 작성해줘"라고 요청합니다. 결과를 검토하고 회신합니다. 제목의 태그는 지우지 않습니다.
4. 웹사이트에서 **메일 확인**을 누릅니다. 개발사항의 1단계가 "완료", 2단계가 "진행중"으로 바뀌고 메일 이력에 회신이 보이면 성공입니다.
5. 개발사 문서는 회사 메일에서 Gmail로 **전달**합니다. 이때 상세 화면의 **전달용 제목 복사**로 복사한 태그를 제목 앞에 붙입니다. 태그를 빠뜨리면 미분류함으로 갑니다.

## 7. 문제 해결

| 증상 | 확인할 것 |
|---|---|
| 발송 실패 "Invalid login" / 535 | 일반 비밀번호가 아니라 **앱 비밀번호**인지, 2단계 인증이 켜져 있는지 |
| 회사 메일에 도착하지 않음 | 스팸함, 회사의 외부 메일 차단 정책 |
| 회신했는데 메일 확인에서 0건 | 회신이 Gmail 받은편지함에 도착했는지(필터로 다른 곳에 보관되지 않았는지), 처음 확인이라면 최근 3일 안의 메일인지 |
| 회신이 미분류함으로 감 | 제목 태그를 지웠고, 회신 헤더와 본문 표식도 없는 경우. 미분류함에서 개발사항을 지정합니다 |
| "최근 24시간 발송 한도" 오류 | `MAIL_DAILY_LIMIT` 값을 늘립니다 |

## 8. 시뮬레이터로 연습하기

**설정 → 시뮬레이터 샘플 메일**에서 개발사항을 고르고 샘플을 넣은 다음 **메일 확인**을 누르면, 실제 수신과 같은 과정으로 처리됩니다. 샘플은 모두 합성 데이터입니다.

| 샘플 | 결과 |
|---|---|
| ① Copilot 수집 회신 | 1단계 완료, 2단계 진행중 |
| ② Architecture md 전달 / ③ QA md 전달 | 메일 이력에 첨부와 함께 등록 (문서 유형 판별과 검토는 P4) |
| ④ 진행상황 회신 | 6단계 완료 (마일스톤 표는 P5) |
| ⑤ 태그 없는 전달 메일 | 미분류함으로 이동 |
