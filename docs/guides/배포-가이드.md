# AX_AIDD 무료 공인 배포 가이드

| 항목 | 내용 |
|---|---|
| 작성일 | 2026-11-21 |
| 대상 | P1 결과물 (로그인, 트리, 개발사항 진행 단계) |
| 구성 | GitHub(비공개 저장소) → **Vercel**(웹, 무료 Hobby) + **Neon**(Postgres, 무료) |
| 결과 | `https://<프로젝트명>.vercel.app` 공인 주소 |

> **Vercel Hobby 요금제는 개인·비상업 용도 조건**입니다. 회사 업무에 써도 되는지는 사용자가 판단해야 합니다. 안 된다면 Render 무료 웹서비스로 바꿀 수 있습니다(9장).

## 1. 준비물 (계정은 모두 무료)

| 서비스 | 용도 | 가입 |
|---|---|---|
| GitHub | 코드 저장소. Vercel이 여기서 자동 배포 | github.com |
| Neon | Postgres DB | neon.tech (GitHub 계정으로 가입 가능) |
| Vercel | 웹 호스팅 | vercel.com (GitHub 계정으로 가입 권장) |

## 2. 코드를 GitHub에 올리기

1. GitHub에서 **비공개(Private)** 저장소를 만듭니다. 예: `ax-aidd`
2. 작업 폴더(`c:\work\workspace_pmday1`)에서 저장소를 초기화하고 올립니다. Claude에게 "git 초기화하고 커밋해줘"라고 요청해도 됩니다.

```powershell
cd c:\work\workspace_pmday1
git init -b main
git add .
git commit -m "AX_AIDD P1"
git remote add origin https://github.com/<계정>/ax-aidd.git
git push -u origin main
```

- `.env.local`, `web/.data/`(로컬 DB), `node_modules`는 `.gitignore`에 들어 있어 올라가지 않습니다.

## 3. Neon DB 만들기

1. Neon 콘솔에서 **New Project**를 만듭니다.
   - 이름: `ax-aidd`
   - 리전: 가까운 아시아 리전 (예: Singapore)
2. **Connection string**을 복사합니다. `postgresql://...neon.tech/...?sslmode=require` 형식입니다.
3. 이 값이 4장의 `DATABASE_URL`입니다.
4. 테이블은 앱이 처음 실행될 때 자동으로 만들어집니다. 별도 작업은 필요 없습니다.

## 4. Vercel에 배포하기

1. Vercel에서 **Add New → Project**를 누르고, GitHub의 `ax-aidd` 저장소를 **Import**합니다.
2. 설정 화면에서 다음을 입력합니다.
   - **Root Directory: `web`** (반드시 지정)
   - Framework Preset: Next.js (자동으로 잡힘)
   - **Environment Variables:**

| 이름 | 값 |
|---|---|
| `LOGIN_ID` | 로그인 아이디 |
| `LOGIN_PASSWORD` | **강한 비밀번호** (공인 사이트이므로 필수) |
| `AUTH_SECRET` | 임의의 긴 문자열 (아래 명령으로 생성) |
| `DATABASE_URL` | 3장의 Neon 연결 문자열 |

`AUTH_SECRET` 생성 (PowerShell):
```powershell
[Convert]::ToBase64String((1..48 | ForEach-Object { Get-Random -Maximum 256 }))
```

3. **Deploy**를 누릅니다. 1~2분 뒤 `https://<프로젝트명>.vercel.app`이 열립니다.
4. 함수 리전을 DB와 가깝게 맞춥니다: **Settings → Functions → Function Region**에서 Neon과 같은 지역(예: Singapore)을 선택합니다. 응답 속도가 좋아집니다.

이후로는 GitHub `main`에 push할 때마다 자동으로 다시 배포됩니다.

### 대안: GitHub 없이 CLI로 바로 배포

```powershell
cd c:\work\workspace_pmday1\web
npx vercel login          # 브라우저에서 로그인
npx vercel                # 첫 배포 (질문에 답하면 프로젝트 생성)
npx vercel env add LOGIN_ID production    # 4장의 환경 변수 4개를 각각 추가
npx vercel --prod         # 운영 배포
```

## 5. 배포 후 확인

1. `https://<프로젝트명>.vercel.app` 접속 → 로그인 화면으로 이동하는지 확인
2. 설정한 계정으로 로그인
3. 단위서비스 → 라벨링 → 개발사항을 만들고, 드래그 이동과 단계 변경을 확인
4. 새로고침해도 데이터가 남아 있는지 확인 (Neon에 저장됨)

## 6. 문제 해결

| 증상 | 원인과 조치 |
|---|---|
| 로그인 시 "로그인 설정이 없습니다" | Vercel 환경 변수 `LOGIN_ID`, `LOGIN_PASSWORD`, `AUTH_SECRET` 중 빠진 것이 있음 → 추가한 뒤 **Redeploy** |
| "서버 오류가 발생했습니다" | Vercel → 프로젝트 → **Logs**에서 오류 확인. 대부분 `DATABASE_URL` 오타 |
| 첫 요청이 몇 초 느림 | Neon 무료 DB가 쉬다가 깨어나는 시간. 정상 |
| 빌드 실패 "Cannot find module" | Root Directory가 `web`인지 확인 |

## 10. 다중 사용자 설정 (약 5명)

2026-11-22부터 여러 명이 각자의 아이디·비밀번호로 로그인하고, 로그인한 계정의 Gmail 설정으로 메일을 주고받습니다. 업무 데이터(트리·메일·문서)는 모두가 함께 봅니다. 기준: [상단 초기화·다중 사용자 계획](../proposals/2026-11-22_상단-초기화-다중사용자-계획.md)

`AUTH_USERS`가 없으면 기존 방식(`LOGIN_ID` / `LOGIN_PASSWORD`, 전역 `GMAIL_*`)이 그대로 동작합니다.

### 10.1 관리자가 할 일

1. 사용자마다 비밀번호 해시를 만듭니다. 비밀번호 원문은 Vercel에 넣지 않습니다.
   ```powershell
   cd web
   npm run hash-password      # 비밀번호(8자 이상)를 입력하면 scrypt$... 값이 나옴
   ```
2. Vercel → Settings → Environment Variables에 넣습니다. ID는 영문 소문자·숫자·`-`·`_` 1~32자입니다(예: `1`, `hak`). 환경 변수 이름에는 ID를 **대문자**로 쓰고 `-`는 `_`로 바꿉니다(예: `kim-a` → `USER_KIM_A_`).

| 이름 | 예 | 설명 |
|---|---|---|
| `AUTH_USERS` | `hak,kim,lee` | 로그인할 수 있는 ID 목록 (쉼표 구분) |
| `USER_HAK_PASSWORD_HASH` | `scrypt$...` | **로그인 비밀번호는 여기에** 1에서 만든 해시 값으로 넣습니다. 없으면 그 ID는 로그인 불가 |
| `USER_HAK_NAME` | 이름 | 머리글에 표시 (선택) |
| `AUTH_SECRET` | (기존 값 유지) | 세션 쿠키 서명·내 메일 설정 암호화. 바꾸면 모두 다시 로그인하고, `SETTINGS_ENCRYPTION_KEY`가 없으면 화면에서 저장한 앱 비밀번호도 다시 입력해야 합니다 |
| `SETTINGS_ENCRYPTION_KEY` | 임의의 긴 문자열 | 선택. 내 메일 설정 암호화 키를 `AUTH_SECRET`과 분리할 때 |

Gmail 주소·앱 비밀번호·회사 메일(수집 요청 주소)은 **각 사용자가 로그인 후 설정 → ‘내 메일 설정’에서 직접 입력**합니다(앱 비밀번호는 암호화 저장). 관리자가 기본값을 미리 넣고 싶을 때만 `USER_HAK_GMAIL_ADDRESS`, `USER_HAK_GMAIL_APP_PASSWORD`, `USER_HAK_COLLECT_TO_ADDRESS`를 씁니다. 사용자가 화면에 입력한 값이 우선합니다.

3. **Redeploy**합니다. 환경 변수는 다시 배포해야 반영됩니다.

### 10.2 운영

| 작업 | 방법 |
|---|---|
| 사용자 추가 | `AUTH_USERS`에 ID를 추가하고 `USER_<ID>_PASSWORD_HASH`(필요하면 `_NAME`)를 넣은 뒤 Redeploy. 메일 설정은 사용자가 로그인해서 입력 |
| 비밀번호 초기화 | 새 해시로 `USER_<ID>_PASSWORD_HASH`를 바꾸고 Redeploy. 그 사용자의 기존 로그인은 끊깁니다 |
| 사용자 중지 | `AUTH_USERS`에서 ID를 빼고 Redeploy. 기존 로그인도 끊깁니다 |
| 로그인 실패 | 같은 ID로 5번 실패하면 15분 동안 차단됩니다(서버 인스턴스 메모리 기준) |

- 설정 화면의 ‘내 메일 설정’에는 **로그인한 사용자 자신의** 값만 보이고 수정할 수 있습니다. 앱 비밀번호는 "설정됨" 여부만 표시하며, 바꾸거나 지울 수만 있습니다. 저장 후 ‘연결 테스트’로 확인합니다.
- Gmail 발송 한도(`MAIL_DAILY_LIMIT`)와 수신 위치는 Gmail 계정별로 따로 관리합니다.
- 같은 메일이 여러 사용자 메일함에 있으면 한 번만 기록합니다(Message-ID 기준).

### 10.3 시연 데이터 초기화

- 머리글의 **시연 데이터 초기화** 버튼은 로그인한 누구나 누를 수 있으며, 시연 데이터만 지우고 6개 단위서비스 시연 데이터를 새로 만듭니다. 사용자가 직접 만든 실제 업무 데이터는 지우지 않습니다.
- 시연 데이터 아래에 새로 만든 항목도 시연 데이터로 취급되어 초기화 때 함께 지워집니다. 시연 데이터와 실제 데이터 사이의 드래그 이동은 막혀 있습니다.
- 시연 개발사항에서 실제 Gmail로 보낼 때는 본인 수집 요청 주소·Gmail 주소로만 보낼 수 있습니다(시연 담당자 주소로 실제 메일이 나가지 않게).
- 개발사항 코드는 초기화해도 되돌리지 않아 초기화할 때마다 번호가 커집니다(실제 자료와 겹치지 않게).
- **DB 마이그레이션 `0006`이 처음 배포될 때, 그때까지 DB에 있던 자료는 모두 시연 데이터로 표시됩니다**(2026-11-22 사용자 확인: 기존 자료는 모두 시연용). 배포 전에 실제 업무 자료를 넣지 마세요. 필요하면 Neon 콘솔에서 배포 전 브랜치(백업)를 만들어 둡니다.
