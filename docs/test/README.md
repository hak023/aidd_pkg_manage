# 시험 체계

문서 규칙은 [AGENTS.md](../../AGENTS.md) 3장을 따릅니다. 단계별 진행 현황은 [docs/dev/README.md](../dev/README.md)에 있습니다.

## 1. 시험 종류

| 종류 | 도구·방법 | 무엇을 확인하나 | 언제 |
|---|---|---|---|
| **A. 자동 단위·저장소** | Vitest + 메모리 PGlite (`web/tests/*.test.ts`), `npm test` | 순수 로직(규칙, 파싱, 검증), DB 저장소 흐름. 외부 연동은 모의(시뮬레이터, 모의 LLM, fetch 대체) | 코드 변경마다 |
| **B. 브라우저 시나리오** | 화면 없이 띄운 Edge(playwright-core)로 실제 개발 서버 조작. 별도 시험 계정·시험 DB로 실행 | 화면 동작, 단계 진행, 콘솔 오류 0건, 스크린샷 확인 | 단계 완료 전 |
| **C. 실제 연동** | 실제 Gmail·Gemini로 같은 흐름 실행 (합성 자료 사용) | 접속, 응답 형식, 결과 품질 | 연동 기능을 바꿨을 때 |
| **D. 사용자 시험** | 사용자가 실제 업무 자료로 실행 | 실무에 쓸 수 있는지 (D-02 성공 기준) | 단계 완료 후, 시연 전 |

**정적 점검:** 매번 `npm run typecheck`, `npm run lint`를 실행하고, 단계 완료 전에는 `next build`도 실행합니다.

## 2. TC ID와 결과 표기

- **ID 형식:** `TC-P{n}-{번호}`
  - A종 자동 시험: 번호만 붙입니다(`TC-P3-05`). 테스트 이름이 이 ID로 시작합니다.
  - B·C·D종: 번호 앞에 종류 글자를 붙입니다(`TC-P3-B1`, `TC-P3-R1`, `TC-P3-U1`).
- **결과 표기:**
  - **통과:** 기대 결과대로 동작함
  - **실패:** 기대 결과와 다름. 원인과 조치를 함께 적습니다.
  - **미확인:** 실행하지 못함. 이유를 적고, 통과로 적지 않습니다.
- **시험 자료:** 합성 자료만 씁니다. 실제 메일·고객 정보는 저장소에 넣지 않습니다.

## 3. 브라우저 시나리오 실행 방법

1. 시험용 서버를 띄웁니다. 시험 계정, 시뮬레이터, 시험 DB는 환경 변수로 덮어씁니다.
   - 프로세스 환경 변수가 `.env.local`보다 우선하므로, 사용자의 계정과 DB에 영향을 주지 않습니다.
   ```powershell
   $env:LOGIN_ID="e2e"; $env:LOGIN_PASSWORD="e2e-pass"; $env:AUTH_SECRET="<32자 이상>"
   $env:SIMULATOR_MODE="true"; $env:LLM_MOCK="true"   # 실제 Gemini 시험(C종)은 LLM_MOCK="false"
   $env:PGLITE_DIR="<임시 폴더>"
   npm run dev -- -p 3200
   ```
2. 시나리오 스크립트(playwright-core, 설치된 Edge 사용)로 로그인부터 단계 진행까지 실행합니다.
3. 콘솔 오류 수와 스크린샷을 확인하고, 결과를 단계 시험 문서에 적습니다.
