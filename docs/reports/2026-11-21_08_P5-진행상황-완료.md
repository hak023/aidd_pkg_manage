### 2.1 구현

| 기능 | 내용 |
|---|---|
| 진행상황 요청 메일 | 수집 요청과 같은 구조입니다(안내 + Copilot 지침 + 4.5 마일스톤 표 양식, 시작·끝 표식). 받는 사람은 config 주소로 고정됩니다. 발송 전 미리보기 창이 있고(수집 요청과 공용 `RequestMailDialog`), 발송하면 6단계가 진행중이 됩니다 |
| L6 해석 | 양식 표는 코드(규칙 해석기)로 읽고, 표가 깨졌을 때만 Gemini를 씁니다. 스키마로 이름·상태를 enum으로 묶고 4행으로 고정합니다. 날짜는 정규화하고, 값이 없으면 "미정"으로 둡니다 |
| 단계 진행 | 해석에 성공하면 6단계 완료, 실패하면 기록만 하고 보류합니다(G-05). P2의 "수신하면 완료"를 바꿨습니다 |
| 이력·변경 | 회신마다 기록을 쌓고, 직전 기록 대비 바뀐 상태·날짜를 표시합니다 |
| 직접 입력·다시 해석 | Gmail 없이 회신을 붙여 넣을 수 있고, 최신 회신을 다시 해석할 수 있습니다 |
| 공유 | 제목은 4.6 양식을 따르고, 본문에 마일스톤 표(미정 포함)를 넣습니다. 첨부는 없고, 두 번 눌러야 발송됩니다 |
| 7단계 | 다른 단계의 상태 요약과 완료 버튼 |
| 대시보드 | "상용적용" 열 (최신 진행상황, 없으면 미정) |
| 전체 시나리오 실행 | 설정 화면 버튼과 자동 시험이 같은 함수를 씁니다. 새 개발사항을 만들어 1~7단계를 진행하고, 단계마다 성공 여부·내용·시간을 보여 줍니다(시뮬레이터 모드) |
| 샘플 | ④-2 일정 변경 재회신, ④-3 표 없는 문장형 회신 (합성) |
| DB | 마이그레이션 `0005_progress`: `progress_reports` |

### 2.2 시험 (자세한 기록은 [test/P5_시험.md](../test/P5_시험.md))

| 범위 | 결과 |
|---|---|
| A 자동 TC-P5-01~12 (전체 75건) | 통과 |
| B 브라우저: 6단계 흐름, 실패와 직접 입력, 완료, 대시보드, 전체 시나리오 | 통과, 콘솔 오류 0건 |
| C 전체 시나리오를 실제 Gemini로 | **1~7단계 모두 통과 (31.7초)** |
| C 표 없는 회신 L6 (실제 Gemini) | 결함 1건을 고치고 품질 1건을 보완한 뒤 통과 (2회 연속) |
| typecheck, lint, build | 통과 |
| D 사용자 시험 | 미확인 |

**실제 Gemini 시험에서 찾아 고친 것**
1. **스키마 오류:** Gemini가 enum 값에 빈 문자열을 허용하지 않아 400 오류가 났습니다.
   - 이때 G-05대로 실패만 기록되고 6단계는 유지되어, 실패 처리가 의도대로 동작함을 함께 확인했습니다.
   - **조치:** "없음"으로 받아 빈 값으로 바꿉니다.
2. **출처 품질:** 출처가 없는 행에 인사말을 출처로 넣었습니다.
   - **조치:** "그 마일스톤 문장의 출처만, 없으면 빈 값"으로 지시했습니다.
