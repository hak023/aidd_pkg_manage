## 1. 요청 내용

- `AUTH_USERS`에 ID를 넣은 뒤 비밀번호는 어느 환경 변수에 넣는가.
- Gmail 주소·앱 비밀번호·회사 메일은 로그인 후 설정에서 수정할 수 있게 계획해 구현.

## 2. 수행 내용

1. 비밀번호 위치 안내: `USER_<ID 대문자>_PASSWORD_HASH`에 `npm run hash-password`로 만든 해시를 넣는다(원문 아님). 배포 가이드 표에 명시.
2. 설계: 기존 결정(메일 설정은 관리자 환경 변수)과 AGENTS.md 5-3(비밀값은 환경 변수에만)을 사용자 요청에 따라 바꿈. 앱 비밀번호는 AES-256-GCM 암호화 후 DB 저장, 응답·화면에는 설정 여부만. 근거를 AGENTS.md와 계획안에 기록.
3. 구현: `user_settings` 테이블(마이그레이션 0007), `lib/secret-box.ts`, `lib/repo/user-settings.ts`, `GET/PUT /api/settings/mail`, 요청마다 내 입력값과 관리자 환경 변수를 합쳐 요청 문맥에 넣도록 `respond()` 변경, 설정 화면 ‘내 메일 설정’ 양식(출처 표시, 앱 비밀번호 바꾸기·지우기).
4. 시험: 자동 88건(TC-P2-15~17 추가), typecheck, lint 통과. 브라우저 시험에서 첫 로드 전 입력이 덮이는 결함을 찾아 입력 칸을 로드 전 비활성화로 조치 후 통과.

## 4. 결정 사항 / 미결 사항

**결정**

- 사용자가 본인 메일 설정을 화면에서 수정한다. 입력값이 관리자 환경 변수보다 우선한다.
- 앱 비밀번호 암호화 키는 `SETTINGS_ENCRYPTION_KEY`, 없으면 `AUTH_SECRET`에서 파생한다.

**미결**

- `AUTH_SECRET`을 바꾸면 화면에서 저장한 앱 비밀번호를 다시 입력해야 한다(`SETTINGS_ENCRYPTION_KEY`를 따로 두면 피할 수 있음).
- 로그인 비밀번호 변경은 여전히 관리자가 환경 변수로 한다(사용자 화면 변경 기능 없음).
- 배포 환경에서 화면 입력값으로 실제 Gmail 송수신은 미확인.
