### 2.2 P2 메일 연동 (`web/`)

**구성**
- Gmail SMTP 발송은 nodemailer, IMAP 수신은 imapflow와 mailparser를 씁니다.
- 앱 비밀번호 방식입니다(서비스 정의 7.1).
- **마이그레이션 `0002_mail`:**

| 테이블 | 내용 |
|---|---|
| `mails` | 발송과 수신 메일 |
| `mail_attachments` | md 첨부는 내용까지 저장 |
| `sim_inbox` | 가상 받은편지함 |
| `app_state` | IMAP 마지막 UID 등 |

**기능**

| 기능 | 내용 |
|---|---|
| 메일 모드 | `SIMULATOR_MODE=true`면 시뮬레이터, Gmail 값 3개가 있으면 Gmail, 로컬에서 값이 없으면 시뮬레이터, 운영에서 값이 없으면 "설정 필요" |
| 수집 요청 메일 | 미리보기 창에서 받는 사람, 제목, 본문을 확인하고 발송합니다. 본문은 사람용 안내, Copilot 지침, 회신 양식(시작·끝 표식)으로 구성합니다(부록 A). 받는 사람은 `COLLECT_TO_ADDRESS`로 고정(자동 발송 규칙). 여러 번 보낼 수 있고, 발송하면 1단계가 진행중이 됩니다 |
| 메일 확인 | 머리글 버튼, 화면을 열어 둔 동안 2분마다 자동 확인, 외부 크론용 `GET /api/mail/poll?secret=` |
| 수신 범위 | 태그나 표식이 있거나, 회사 주소에서 온 메일만 기록합니다. 처음 확인할 때는 최근 3일만 봅니다. 같은 Message-ID는 한 번만 기록합니다 |
| 매칭 | 제목 태그, 회신 헤더(In-Reply-To/References), 본문 표식 순서로 찾습니다 |
| 단계 진행 | 수집 회신이 오면 1단계 완료, 2단계 진행중. 진행상황 회신이 오면 6단계 완료. 문서 전달 메일은 이력만 남깁니다(유형 판별은 P4) |
| 미분류함 | 매칭하지 못한 메일을 개발사항에 지정하거나, 무시하거나, 되돌립니다. 머리글에 개수를 표시합니다 |
| 메일 이력 | 개발사항 상세에 발송·수신 목록을 보여 주고, 본문과 첨부(md) 보기 창을 둡니다 |
| 설정 화면 | 현재 config 확인(비밀값은 설정 여부만), 외부 크론 주소, 시뮬레이터 샘플 주입 |
| 시뮬레이터 | 합성 샘플 5종: Copilot 회신, Architecture md, QA md, 진행상황 회신, 태그 없는 전달 |
| 발송 한도 | 최근 24시간 실제 발송 30건(`MAIL_DAILY_LIMIT`, R3) |

## 4. 결정 사항 / 미결 사항

**결정 (구현하며 정한 것)**
- **Gmail 수신 범위:** 받은편지함 전체를 기록하지 않습니다. 태그, 표식, 회사 주소 발신 중 하나에 해당하는 메일만 기록합니다. 개인 메일이 섞이지 않게 하기 위함입니다.
- **진행상황 회신:** 받으면 6단계를 완료로 바꿉니다(완료 조건 그대로). 마일스톤 표 파싱은 P5에서 합니다.
- **문서 전달 메일:** 이력과 첨부만 저장합니다. Architecture/QA 판별과 단계 진행은 P4(L3)에서 합니다.

**미결 (사용자 확인 필요)**
1. **GitHub push 403:** 이 PC에 저장된 GitHub 자격 증명이 저장소 쓰기 권한이 없는 토큰입니다. 둘 중 하나를 해 주세요.
   - Windows "자격 증명 관리자" → Windows 자격 증명 → `git:https://github.com` 삭제 후 다시 push해서 브라우저 로그인
   - 이 저장소에 Contents 쓰기 권한이 있는 토큰으로 교체
2. **Gmail 값 입력:** 사용자가 직접 `web/.env.local`(로컬)과 Vercel 환경 변수(배포)에 값을 넣어야 합니다. 이 작업 환경은 보안 규칙상 `.env*` 파일을 다루지 않습니다.
   - 필수: `GMAIL_ADDRESS`, `GMAIL_APP_PASSWORD`, `COLLECT_TO_ADDRESS`
   - 외부 크론용: `POLL_SECRET`
3. 실제 Gmail ↔ 회사 메일 송수신 확인(위험 R4, R5). 메일 연동 가이드 6장 순서로 확인합니다.
