## 1. 요청 내용

변경 사항을 배포해 주면 확인해 보겠다.

## 2. 수행 내용

- 배포 방식은 GitHub `main` push 후 Vercel 자동 배포다 (배포 가이드 4장).
- 작업 트리에 이 대화의 변경(#01 문구, #04 프롬프트 공개)과 다른 세션의 변경(#03 시연 데이터 단일 시나리오)이 함께 있었다. 사용자가 둘 다 배포하기로 결정했다.
- 커밋 2개로 나눴다.
  1. 시연 데이터 단일 시나리오 (#03)
  2. 4·5단계 안내 문구 변경, 프롬프트 공개(P6), 오늘 리포트·색인 (#01, #02, #04, #05). 두 작업의 수정이 한 파일에 섞인 색인 3개(`docs/dev/README.md`, `docs/reports/README.md`, `web/README.md`)도 여기에 넣었다.
- push 전 확인: `npm test` 91건 통과, typecheck 오류 0건, lint 통과, `next build` 통과 (두 변경을 합친 상태). `.env` 파일은 변경 목록에 없음.
- **push 실패:** `git push origin main`이 `403 Permission denied`로 거부됐다. 이 PC에 저장된 GitHub 토큰(Windows 자격 증명)에 쓰기 권한이 없다. 2026-11-21 #02와 같은 문제다.
  - SSH도 시도했다. 22번 포트는 회사망에서 막혀 있고, 443번 포트는 키가 GitHub 계정에 등록되어 있지 않아 거부됐다 (이 과정에서 `~/.ssh/known_hosts`에 `ssh.github.com:443` 호스트 키가 추가됨).
  - Vercel CLI는 이 PC에 로그인·연결되어 있지 않다.
  - 따라서 커밋 2개는 로컬 `main`에만 있다 (origin/main보다 2개 앞섬). 배포되지 않았다.

## 4. 결정 사항 / 미결 사항

**결정**

- 다른 세션의 시연 데이터 변경도 함께 배포 (사용자 결정).

**미결 (사용자 확인 필요)**

- **push:** 사용자가 `.\scripts\git-push.ps1 -ResetCredential`을 실행해 브라우저에서 저장소 소유 계정으로 다시 로그인해야 한다. push되면 Vercel이 자동으로 배포한다.
- Vercel 배포 완료와 운영 화면 확인은 사용자가 한다. 이 PC에서는 Vercel 배포 상태와 운영 주소를 확인하지 않았다.
- 시연 데이터 변경은 머리글 `시연 데이터 초기화`를 눌러야 운영 DB에 반영된다. 누르면 모든 사용자가 함께 보는 시연 자료가 바뀐다.
- 운영 사이트가 실제 Gemini를 쓰면 2~5단계 화면에서 TC-P6-R1(모델명 표시)을 확인할 수 있다.
