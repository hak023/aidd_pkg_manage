## 1. 요청 내용

공유 업무 데이터, 사용자별 로그인과 Gmail 설정, 시연 데이터만 초기화하는 머리글 버튼을 구현한다.

## 2. 수행 내용

1. 사용자 결정 반영: 기존 자료는 모두 시연 데이터, 자동 메일 확인은 사이트를 연 사용자만(외부 크론 미사용).
2. 기존 초기화가 전체 테이블을 지우는 위험이 있어 먼저 API·CLI를 임시 차단하고, 시연 범위 분리 구현 후 다시 열었다.
3. 시연 데이터 범위: `nodes.is_demo`, `mails.is_demo`(마이그레이션 0006). 초기화는 시연 데이터만 지우고 재생성, DB 잠금으로 동시 실행 방지, 실패 시 시연 데이터 정리. 실제 업무 데이터·개발사항 코드 보존. 시연↔실제 간 이동 거부. 시연 개발사항의 실제 Gmail 발송은 본인 주소로만.
4. 다중 사용자: `AUTH_USERS` + `USER_<ID>_*` 환경 변수, scrypt 비밀번호 해시(`npm run hash-password`), 비밀번호 변경·계정 삭제 시 세션 무효, 로그인 실패 5회 15분 차단. `AUTH_USERS`가 없으면 기존 단일 계정 방식 유지.
5. 사용자별 메일: 요청마다 로그인 사용자 문맥을 두고 메일 config가 그 사용자 값을 사용. 수신 위치·발송 한도·폴링 잠금을 Gmail 계정별로 분리. 외부 크론 경로 제거.
6. 화면: 머리글에 `시연 데이터 초기화` 버튼(확인 창·결과 알림)과 사용자 이름. 설정 화면은 로그인 사용자의 메일 설정만 표시.
7. 시험: 자동 85건, typecheck, lint 통과. 시험 계정 2개·임시 DB로 API·브라우저 시나리오 통과(TC-P1-B3).

## 4. 결정 사항 / 미결 사항

**결정**

- 업무 데이터 공유, 로그인·메일 설정은 사용자별(관리자가 Vercel 환경 변수로 관리).
- 머리글 버튼은 로그인한 누구나 사용, 시연 데이터만 초기화.
- 배포 시점까지의 기존 자료는 모두 시연 데이터로 표시(사용자 확인).
- 자동 메일 확인은 사이트를 연 사용자만, 외부 크론 제거.
- Neon HTTP는 다문장 트랜잭션을 지원하지 않아, 원자적 교체 대신 DB 잠금 + 실패 시 시연 데이터 정리로 복구.

**미결 (사용자 확인 필요)**

- GitHub main push 완료(`c318e62`, 사용자 승인). Vercel 자동 배포 결과와 Neon 0006 적용은 미확인.
- 사용자 5명의 ID·이름, 사용자별 Gmail 계정 준비(각자 2단계 인증·앱 비밀번호).
- Neon에서의 0006 적용·초기화, 실제 Gmail 사용자별 송수신은 미확인(배포 후 확인).
