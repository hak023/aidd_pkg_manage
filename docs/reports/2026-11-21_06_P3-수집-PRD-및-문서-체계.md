## 2. 수행 내용

### 2.1 개발·시험 문서 체계

AGENTS.md에 3장을 새로 두었습니다. CLAUDE.md는 AGENTS.md를 불러오므로 규칙은 한 곳에서 관리됩니다.

**문서 4종**

| 문서 | 위치 | 성격 |
|---|---|---|
| 진행 현황 | `docs/dev/README.md` | 계속 갱신 |
| 단계 설계 | `docs/dev/P{n}_주제.md` | 구현 전에 작성하고, 구현하며 갱신 |
| 시험 체계 | `docs/test/README.md` | 체계가 바뀔 때 갱신 |
| 단계 시험 | `docs/test/P{n}_시험.md` | TC 목록과 실행 기록을 쌓음 |

**운영 규칙**
- **TC ID:** `TC-P{n}-{번호}` 형식입니다. 자동 테스트 이름도 이 ID로 시작해, 문서와 코드를 연결합니다.
- **시험 종류:** A 자동, B 브라우저, C 실제 연동, D 사용자 시험
- **결과 표기:** 통과 / 실패(원인과 조치) / 미확인(이유)
- **실제 연동을 못 한 항목:** "미확인"으로 남깁니다.

**기존 단계 문서 소급 작성**
- P1과 P2의 설계·시험 문서를 기존 리포트를 바탕으로 작성했습니다.
- 기존 자동 테스트 34건에 TC ID를 붙였습니다(TC-P1-01~21, TC-P2-01~13).

### 2.2 P3 구현

설계 문서([P3_수집-PRD.md](../dev/P3_수집-PRD.md))를 먼저 쓰고 그에 따라 구현했습니다.

| 기능 | 내용 |
|---|---|
| L1 회신 점검 | 회신 양식 구간을 추출합니다(인용된 빈 양식은 건너뜀). 12개 항목별 상태(충분·부족·확인 안 됨), 상충, 출처 없는 진술, 관련자, 추가 질문을 만듭니다. JSON 스키마로 응답을 받고, 형식이 틀리면 1회 재시도합니다. 그래도 실패하면 기록만 하고 단계는 진행하지 않습니다(G-05) |
| 추가 입력 | 질문별 답, 보완 메모, 저장 |
| L2 PRD 생성 | 5.3 양식의 12개 장. 머리글과 변경 이력은 코드가 만듭니다. 12개 장이 모두 있는지 검사합니다. 담당자 입력은 `[담당자 보완 날짜]`로 표기합니다 |
| 문서 버전 | 편집·미리보기를 나란히 둡니다. 저장할 때마다 새 버전이 생기고, 버전 선택과 내려받기를 할 수 있습니다. 미리보기는 HTML을 실행하지 않습니다 |
| PRD 공유 | 수신자 기본값은 관련자이며, 편집하고 형식을 검사합니다. 제목·본문을 편집할 수 있고 첨부명을 보여 줍니다. "보내기 → 발송 확인"을 눌러야 발송됩니다. 발송하면 3단계가 완료됩니다 |
| LLM 선택 | `LLM_MOCK` → Gemini 키 → 로컬은 모의 / 운영은 오류. 작업별 모델(`GEMINI_MODEL_REVIEW`, `GEMINI_MODEL_PRD`) |
| DB | 마이그레이션 `0003_prd`: `reviews`, `documents` |

### 2.3 시험 (자세한 기록은 [test/P3_시험.md](../test/P3_시험.md))

| 범위 | 결과 |
|---|---|
| A 자동 TC-P3-01~12 (전체 46건) | 통과 |
| B 브라우저: 전체 흐름, HTML 이스케이프 | 결함 1건을 고친 뒤 통과. 콘솔 오류 0건 |
| C 실제 Gemini L1·L2 (합성 회신) | 통과. `gemini-3.5-flash-lite` 자동 선택, L1 7.5초, L2 4.9초, 12개 장, 지어낸 내용 없음 |
| typecheck, lint, build | 통과 |
| D 사용자 시험 | 미확인 (실제 Copilot 회신 필요) |

**시험 중 발견해 고친 결함**
1. PRD v2를 저장한 직후 "공유"를 누르면, 공유 창 대신 "저장하지 않은 변경" 오류가 나왔습니다. 저장 응답의 문서를 바로 현재 문서로 쓰도록 고쳤습니다.
2. PRD 작성일이 UTC 기준으로 하루 이르게 표시되었습니다. 한국 시간 기준으로 고쳤습니다.

**시험 환경:** 사용자의 `.env.local` 계정과 로컬 DB를 건드리지 않도록 별도 시험 서버(포트 3200)를 띄웠습니다.
- 시험 계정, 시뮬레이터, 임시 DB는 환경 변수로 덮어썼습니다.
- Gemini 키는 서버 안에서만 쓰였고, 작업 환경에서 읽지 않았습니다.
- 시험 후 사용자 서버(포트 3100)를 다시 실행했습니다.
