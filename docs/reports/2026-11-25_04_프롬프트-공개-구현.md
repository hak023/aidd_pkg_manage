## 1. 요청 내용

A 방식으로 보여 주면 된다. 공개 대상은 로그인한 사용자에게만. 범위는 2단계도 포함. 전송본 저장은 필요하지 않고, 동작을 투명하게 보여 주는 것이 목적이므로 고정값을 출력. 시연 데이터 표기는 변경 없이 지금처럼. 공유 메일에는 작성 방식을 넣지 않아도 됨.

## 2. 수행 내용

- 결정 6건을 계획안 0장에 기록했다. 문서 단계는 답이 없어 제안대로 P6으로 분리했다.
- 2·3·4·5단계를 선택하면 단계 설명 카드에 작성·검토 방식을 표시한다: 입력 자료, LLM에 보내는 지시, 시스템이 하는 처리, 그리고 시스템 지시문·작업 지시문·응답 형식의 원문(펼쳐서 봄, 복사 버튼).
- 원문은 실제 호출에 쓰는 코드에서 얻는다. 자료가 들어가는 자리만 `{수집 회신 본문}`처럼 표시한다.
- 원문은 로그인이 필요한 API(`GET /api/prompts`)로만 내려 준다.
- DB는 바꾸지 않았다.
- 자세한 내용은 [P6 설계](../dev/P6_프롬프트-공개.md), 시험 결과는 [P6 시험](../test/P6_시험.md)에 있다.

**검증**

- `npm test` 91건 통과, `npm run typecheck` 오류 0건, `npm run lint` 통과, `npm run build` 통과.
- 브라우저(시험 계정, 임시 DB, 모의 LLM)에서 2~5단계 표시와 1·6단계 미표시를 확인했다. 콘솔 오류 0건.
- 로그인 없이 API를 부르면 401이고, 빌드된 정적 JS에는 프롬프트 문자열이 없다.

## 4. 결정 사항 / 미결 사항

**결정**

- 계획안 0장의 7건.
- 원문은 기본으로 접어 두고, 흐름 3칸은 항상 보이게 했다.

**미결 (사용자 확인 필요)**

- 원문을 기본으로 펼쳐 둘지. 지금은 접혀 있어 한 번 눌러야 보인다.
- 5단계 QA 지시문 첫 문장이 "…시험 항목이 없으면 미반영이다를 판정한다."로 어색하게 이어진다. 기존 프롬프트 그대로이고 이번에 화면에 드러났다. 프롬프트 수정은 범위 밖이어서 고치지 않았다. 고치면 실제 Gemini로 QA 검토를 다시 확인해야 한다.
- 실제 Gemini 설정에서의 화면 표시(TC-P6-R1)는 확인하지 못했다.
- AGENTS.md 3장의 "개발 단계(P1~P5 …)" 문구에 P6을 반영할지.
