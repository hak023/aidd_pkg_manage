## 1. 요청 내용

- 시연에는 개발사항 하나를 단계별로 준비해 쓴다. 기존의 많은 시연 자료는 모두 삭제한다.
- 새 자료: `음성링고 / R164PKG_26.12 / 계절·명절 인사말 자동 추천 템플릿 및 예약 일괄 전환 서비스`의 1~7단계 진행 자료.
- 관련자로 허유진, 이승학, 옥수빈을 넣어 상세히 구성한다.
- 화면의 `시연 데이터 초기화` 기능이 이 자료로 초기화되게 한다.

## 2. 수행 내용

1. 구현 전에 두 가지를 사용자에게 확인했다(4장 결정).
2. 기존 시연 원본(6개 단위서비스 카탈로그 파일 5개)을 삭제하고 시나리오 하나로 다시 작성했다.
   - `catalog.ts`: 단위서비스·라벨링·개발사항, 관련자 3명, 히스토리 6건, 기능 요구사항 5건·비기능 3건과 각 요구사항의 Architecture·QA 대조 결과
   - `timeline.ts`: 스냅샷 공통 일정과 초기화 시점에 따른 주 단위 앞당김
   - `builders.ts`: 수집 요청·회신·L1 점검·담당자 답, PRD v1·v2, 개발사 `architecture.md`·`qa.md`와 검토 리포트, 진행상황 요청·회신 3회
3. 생성 엔진(`demo-seed.ts`)을 무작위 생성에서 고정 스냅샷 7개 생성으로 바꿨다. 지우기·잠금·실패 시 정리·코드 채번은 그대로다. `POST /api/demo/seed`와 `npm run seed:demo`는 같은 함수를 부르므로 따로 고치지 않았다.
4. 머리글 버튼의 설명 문구와 완료 알림 문구를 새 구성에 맞췄다.
5. 자동 시험을 새 구성에 맞게 고치고(TC-P1-22·25·26·27), TC-P1-29·30을 추가했다. 기존의 "6개 단위서비스 카탈로그·무작위 생성" 시험 2건은 대체했다.
6. 확인: 자동 시험 88건, typecheck, lint, build 통과. 임시 DB·시뮬레이터·모의 LLM으로 띄운 서버에서 머리글 버튼 초기화와 2~7단계 화면 표시를 확인했다(TC-P1-B4).

자료의 단계별 구성과 일정 규칙은 [P1 설계](../dev/P1_기반.md)에 적었다.

## 4. 결정 사항 / 미결 사항

**결정 (사용자 확인)**
- 같은 개발사항을 1~7단계 상태별로 7개 만든다(단계별 스냅샷).
- 관련자: 허유진(요청, 상품기획(사업 BM)), 이승학(검토, 현장(영업 AM)), 옥수빈(운영·검증, 운용 부서).
- 개발사는 회사명만 쓰고 담당자 이름은 넣지 않는다.

**결정 (구현하며 정한 것)**
- 7개 스냅샷은 이름이 같고 트리의 단계 표시와 코드로 구분한다.
- 7개가 같은 일정을 쓴다. 초기화 시점이 기준 완료일(2026-12-11)보다 이르면 완료가 과거가 되도록 전체 일정을 주 단위로 앞당긴다. 그래서 12월 11일 전에 초기화하면 문서의 상용적용일이 11월로 나온다(오늘 기준 11-19).
- AGENTS.md 5-3에 예외를 추가했다: 시연 데이터의 관련자 3명은 실제 이름·회사 메일 주소를 코드에 둔다. 문서에는 메일 주소를 적지 않는다.
- 실제 Gmail 모드에서 시연 개발사항은 본인 주소로만 발송되는 기존 제한을 그대로 둔다. 공유 창의 받는 사람 기본값에 관련자 3명 주소가 들어가도 본인이 아닌 주소가 있으면 발송이 거부된다.

**미결 (사용자 확인 필요)**
- 12월 11일 전 시연에서 상용적용일이 11월로 보이는 것이 괜찮은지. 12월 날짜를 그대로 보여야 하면 7단계 스냅샷만 미래 날짜를 쓰는 방식으로 바꿀 수 있다.
- 2단계 스냅샷에는 담당자 답 1건만 넣었다. 시연 때 답을 직접 입력하는 장면이 필요 없으면 5건 모두 넣을 수 있다.
- 옥수빈의 부서를 "운용 부서"로 넣었다. 정식 부서명이 따로 있으면 `catalog.ts`에서 바꾼다.
