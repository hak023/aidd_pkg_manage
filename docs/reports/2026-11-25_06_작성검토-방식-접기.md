## 1. 요청 내용

2단계 점검 방식, 3단계 작성 방식, 4·5단계 검토 방식의 데이터가 너무 많아 표시가 좋지 않다. 1줄로 접어서 표현하고 펼칠 수 있도록 변경.

## 2. 수행 내용

- 영역 전체를 기본으로 접었다. 접힌 상태는 한 줄이다: `▶ 작성 방식 · L2 PRD 생성 · 입력 자료, 프롬프트 원문, 시스템 처리`.
- 펼치면 기존 내용(실행 방식, 흐름 3칸, 참고, 원문)이 나온다. 원문은 지금처럼 한 번 더 펼쳐서 본다.
- 내용은 처음 펼칠 때 한 번만 불러온다. 단계를 바꾸면 다시 접힌 상태로 시작한다.
- 한 줄 제목은 프롬프트 없이 `web/src/lib/domain/disclosure.ts`에 두고 서버와 화면이 함께 쓴다. 원문은 여전히 로그인이 필요한 API로만 내려간다.

**검증**

- `npm test` 91건 통과, typecheck 오류 0건, lint 통과, `next build` 통과.
- 브라우저(시험 계정, 임시 DB, 모의 LLM): 접힌 한 줄 높이 20px, 펼치기 전 API 호출 0회, 펼친 뒤 1회, 단계를 바꾸면 접힘, 1·6단계에는 없음, 콘솔 오류 0건.
- 빌드된 정적 JS에는 한 줄 제목만 있고 프롬프트 문자열은 없다.
