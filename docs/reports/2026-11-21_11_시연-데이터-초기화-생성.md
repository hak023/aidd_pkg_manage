## 1. 요청 내용

- 시연을 위해 6개 단위서비스(`전국대표번호`, `음성링고`, `영상링고`, `AI통화비서`, `080착신형AS`, `모두의AI`)를 구성하고 각각 라벨링 3개, 라벨링당 개발사항 2~4개를 랜덤하게 생성.
- 진행 단계는 각 개발사항마다 1~7단계 중 랜덤으로 배정.
- 모든 개발사항과 산출물(메일, 점검 결과, PRD, Architecture 설계서·검토 리포트, QA 시험항목서·검토 리포트, 진행상황 마일스톤)은 시뮬레이터·샘플·예시·가상 티가 나지 않도록 실제 개발 업무 문체로 작성.
- 시연 중 데이터가 수정·삭제되더라도 언제든 전체 초기화 후 다시 입력할 수 있도록 구성하고 배포 환경(Vercel)에도 반영.

## 2. 수행 내용

1. **도메인 맞춤 6개 단위서비스 카탈로그 구축 (`web/src/lib/demo/`)**
   - `전국대표번호`, `음성링고`, `영상링고`, `AI통화비서`, `080착신형AS`, `모두의AI` 서비스별로 분기 패키지 라벨링 3개와 고유 개발사항 설계 원본 12개 이상(총 72개 이상)을 실무 기술 사양 기준으로 작성.
   - `시뮬레이터`, `샘플`, `예시`, `가상`, `모의`, `example.com` 등의 문구·표식 없이 단계별 수집 메일, L1 검토 및 담당자 보완 답변, 12장 구성 PRD(v1/v2), 협력사 Architecture 설계서 및 대조 리포트, QA 시험항목서 및 커버리지 리포트, 진행상황 마일스톤 이력을 자동 조립하는 빌더 구현.
2. **고속 일괄 초기화·적재 엔진 및 인터페이스 구현**
   - `TRUNCATE ... RESTART IDENTITY CASCADE` 및 `dev_code_seq` 리셋으로 변조된 기존 데이터를 완전히 비운 뒤, 청크 단위 배치 `INSERT`로 로컬 PGlite 및 원격 Neon HTTP 모두 1~2초 내 적재 완료되도록 `resetAndSeedDemoData()` 구현.
   - 웹 `설정` 화면 상단에 **데이터 초기화 및 일괄 구성**(`초기화 후 데이터 생성` / `전체 비우기`) 섹션 및 `/api/demo/seed` 라우트 추가.
   - 로컬 CLI 스크립트(`npm run seed:demo` / `npm run seed:demo -- --clear`) 추가 및 로컬 DB 사전 적재 확인.
3. **검증 및 배포 반영**
   - 단위·통합 시험(`web/tests/demo-seed.test.ts`) 추가: 카탈로그 금지어 미포함 검증, 라벨링당 2~4건·1~7단계 정합성 검증, 데이터 임의 변조·삭제 후 재초기화 및 후속 코드 채번 검증(총 78개 테스트 통과).
   - `npm run typecheck`, `npm run lint`, `npm run build` 검증 후 GitHub `main` 브랜치 push 진행.

## 4. 결정 사항 / 미결 사항

**결정**
- 개발사항 생성 단위는 사용자 확인에 따라 **라벨링마다 2~4개 랜덤(전체 36~72건)** 으로 확정.
- 시연 중 언제든 복구할 수 있도록 웹 `설정` 화면 버튼과 CLI 명령을 함께 제공하고 GitHub `main`에 바로 반영.

**미결 (사용자 확인 필요)**
- Vercel 자동 배포 완료 후 배포 사이트(`설정` → `초기화 후 데이터 생성`)에서 한 번 실행하면 운영(Neon) DB에도 즉시 적재됩니다.
