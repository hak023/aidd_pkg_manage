## 2. 수행 내용

### 2.1 서비스 정의 v0.2 확정

- v0.1을 v0.2로 복사하고 답변을 반영했습니다.
  - 단계 운영 규칙: 순서를 강제하지 않고, 완료되지 않은 첫 단계를 "현재 단계"로 표시
  - 전달 메일 태그 방식 추가
  - 공유 도메인 제한 제거
  - 위험 R1, R2, R6에 결정 내용 반영
- v0.1에는 "대체됨"을 표시했습니다.

### 2.2 P1 구현 (`web/`)

**구성**
- Next.js 16.4.6 (App Router, TypeScript, Tailwind 4)
- Drizzle ORM 0.45
- DB: 운영은 Neon(HTTP), 로컬과 테스트는 PGlite(설치가 필요 없는 내장 Postgres)

**기능**

| 기능 | 내용 |
|---|---|
| 더미 로그인 (D-03) | config 계정과 비교, HMAC 서명 쿠키 하나만 사용. `proxy.ts`(Next 16의 미들웨어)가 페이지는 로그인 화면으로, API는 401로 처리 |
| 트리 | 단위서비스 > 라벨링 > 개발사항. 생성, 이름 변경(더블클릭), 드래그 이동, 삭제(하위 항목 경고). 배치 규칙을 서버와 화면 양쪽에서 검사 |
| 개발사항 | `DEV-0001` 형식 코드(재사용하지 않는 시퀀스), 수집 조건(키워드·기간·메모), 전달용 제목 복사(`[AX_AIDD][DEV-xxxx]`) |
| 진행 단계 | 가로 단계 그래프 7단계, 단계별 설명(사용자 할 일 / 시스템 동작 / 완료 조건), 단계마다 상태를 수동으로 변경, 완료 버튼, 이력 기록. 메일·LLM 동작 버튼은 비활성 상태로 연결 예정 단계를 표시 |
| 대시보드 | 단계별 개수, 개발사항 표(현재 단계, 단계 점 표시, 최근 활동) |
| 마이그레이션 | SQL을 코드에 두고 첫 DB 접근 시 자동 적용 (서버리스 배포에서 파일 경로 문제를 피하기 위함) |

### 2.3 검증

| 검증 | 결과 |
|---|---|
| Vitest 21건 (배치 규칙, 현재 단계 계산, 태그·파일명 규칙, 로그인 토큰 서명·만료·변조, 저장소 CRUD·이동·삭제·단계·이력) | 모두 통과 |
| `tsc` / ESLint / `next build` | 통과 |
| HTTP 점검: 비로그인 API 401, 페이지 307, 잘못된 로그인 401, 생성, 잘못된 이동 400, 라벨 없는 위치로 이동, 단계 변경과 이력 | 정상 |
| 브라우저 점검 (headless Edge): 로그인 → 생성 → 단계 변경 → 드래그 이동 → 잘못된 드래그 차단 → 대시보드 | 콘솔 오류 0건, 스크린샷으로 화면 확인 |

### 2.4 구현 중 발견하고 고친 문제

- PGlite가 저장 폴더의 상위 폴더를 만들지 않음 → 먼저 폴더를 생성하도록 수정
- 오류 문구의 조사("라벨링는") → 유형별 조사로 수정
- Git Bash의 `/c/` 경로에서 Vitest가 모듈을 중복으로 불러와 실패 → PowerShell에서 실행하도록 문서화
