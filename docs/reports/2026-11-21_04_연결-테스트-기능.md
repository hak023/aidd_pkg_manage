## 1. 요청 내용

- `POLL_SECRET`에는 무엇을 입력해야 하는지 알려 달라.
- LLM과 Gmail을 테스트하고 결과를 알려 달라.

## 2. 수행 내용

- **Gemini 호출 모듈 추가 (`web/src/lib/llm/gemini.ts`):** REST로 직접 호출하며, 추가로 설치한 패키지는 없습니다.
  - 모델 목록 조회, 텍스트 생성
  - `GEMINI_MODEL`이 비어 있으면 Flash-Lite 안정 버전 중 최신을 자동으로 고릅니다(서비스 정의 5.2).
- **연결 테스트 추가:** `web/src/lib/diag.ts`, `POST /api/settings/test`, 설정 화면의 "연결 테스트" 영역
  - **Gmail 로그인 확인:** 설정값 확인 → SMTP 로그인 → IMAP 로그인과 받은편지함 메일 수
  - **Gmail 테스트 메일 보내기:** 위 확인을 통과하면 `COLLECT_TO_ADDRESS`로 1통을 보냅니다. 보내기 전에 확인 창을 띄웁니다.
  - **Gemini 확인:** 키 확인 → 모델 목록(Flash-Lite 후보) → 짧은 생성 요청 1회(응답 시간, 토큰 수)
  - 결과에는 비밀값을 넣지 않습니다.
- 설정 화면에 `GEMINI_MODEL` 행을 추가했습니다.
- `.env.local`을 불러오도록 개발 서버를 다시 시작했습니다. 서버 로그에서 `Environments: .env.local`을 확인했습니다.
- 타입 검사, 린트, 테스트 34건이 통과했습니다.

### 후속: 사용자 테스트 결과와 조치

**사용자 테스트 결과:** SMTP와 IMAP은 `self-signed certificate in certificate chain`, Gemini 모델 목록은 `fetch failed`로 실패했습니다.

**원인**
- `openssl s_client`로 smtp/imap.gmail.com과 generativelanguage.googleapis.com의 인증서를 확인했습니다. 셋 다 인증서 발급자가 `Kt Corporate Forward Trust CA ECDSA` → `Kt Corporate Root CA`였습니다. 회사망의 SSL 검사 때문입니다.
- 사내 루트 인증서는 Windows 인증서 저장소에는 있지만, Node가 쓰는 인증서 목록에는 없습니다.

**조치**
- Node 22.19의 `--use-system-ca` 옵션으로 Windows 인증서 저장소를 쓰게 했습니다.
  - 이 옵션으로 Gemini 연결(HTTP 403, 키 없는 요청이라 정상), SMTP(authorized true), IMAP(authorized true)을 확인했습니다.
- `package.json`의 `dev`와 `start` 스크립트에 `cross-env NODE_OPTIONS=--use-system-ca`를 추가했습니다.
  - Vercel에는 사내 프록시가 없으므로 영향이 없습니다.
- 개발 서버를 `npm run dev -- -p 3100`으로 다시 시작했습니다.
- `web/README.md`와 메일 연동 가이드의 문제 해결 표에 기록했습니다.

## 4. 결정 사항 / 미결 사항

- **실제 연결 테스트를 실행하지 못했습니다.**
  - `.env.local`에 로그인 계정이 따로 설정되어 있어, 개발용 기본 계정(admin/admin)으로 로그인할 수 없었습니다.
  - 이 작업 환경은 `.env*` 파일을 읽지 않습니다.
- 사용자가 설정 화면에서 테스트 버튼을 누르거나, 로그인 계정을 알려 주면 실행합니다.
