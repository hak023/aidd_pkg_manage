## 1. 요청 내용

3번 PRD 작성, 4번 Architecture 검토, 5번 QA 검토가 어떻게 이루어지는지 화면에 표시하는 것이 중요하다. 작성·검토 프롬프트를 웹 페이지에서 투명하게 원문 공개하는 것을 목적으로, 어느 부분에 어떻게 보여 주면 좋을지 계획을 세운다.

## 2. 수행 내용

- 현재 상태를 코드에서 확인했다: 프롬프트 위치(`web/src/lib/llm/prd.ts`, `docreview.ts`), 실행 경로(`provider.ts`), 3·4·5단계 화면(`ItemDetail.tsx`, `DocPanel.tsx`, `DocReviewPanel.tsx`), DB 스키마.
- 확인한 사실: 프롬프트는 화면에 나오지 않는다. 실제로 보낸 프롬프트는 저장하지 않는다. 모의 LLM과 시연 데이터는 프롬프트를 거치지 않는다. 결과물의 일부(PRD 머리글·변경 이력, 검토 리포트 md와 요약 건수)는 코드가 만든다.
- 계획안을 제안서로 작성했다. 표시 위치 3곳(단계 설명 카드, 문서 카드의 버전별 출처 줄, 프롬프트 공개 페이지), 공개 원칙, 구현 순서, 확인 사항 6건을 담았다.
- 코드는 바꾸지 않았다.

## 4. 결정 사항 / 미결 사항

- 없음 (논의 전).

**미결 (사용자 확인 필요)** — 제안서 6장

1. 공개 대상 (로그인 사용자만 / 로그인 없이도)
2. 범위 (3·4·5단계만 / 2단계 점검 프롬프트 포함)
3. 실제 전송본 저장 방식 (전문 저장 / 지시문만 저장하고 자료는 연결)
4. 시연 데이터를 "시연용 합성 자료 · LLM 실행 기록 없음"으로 표기할지
5. 공유 메일로 나가는 문서에 작성 방식을 넣을지
6. 설계·시험 문서를 P6으로 분리할지
