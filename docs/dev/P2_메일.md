# P2 메일 설계

- 상태: 구현 완료 (2026-11-21). 실제 Gmail은 미확인
- 기준: 서비스 정의 v0.2 — 4장 메일 연동, 7.2 config, 7.3 시뮬레이터
- 시험: [docs/test/P2_시험.md](../test/P2_시험.md) · 사용 안내: [메일 연동 가이드](../guides/메일-연동-가이드.md)
- 작업 기록: 리포트 2026-11-21 [#02](../reports/2026-11-21_02_git-커밋-및-P2-메일-연동.md), [#04](../reports/2026-11-21_04_연결-테스트-기능.md)

## 1. 범위

**포함**
- 수집 요청 메일: 미리보기 후 발송하며, 받는 사람은 `COLLECT_TO_ADDRESS`로 고정됩니다.
- 수신 확인: 버튼, 화면을 연 동안 2분마다 자동 확인, 외부 크론(`GET /api/mail/poll?secret=`)
- 매칭: 제목 태그 → 회신 헤더 → 본문 표식 순서
- 미분류함, 메일 이력, 설정 화면, 연결 테스트
- 시뮬레이터(가상 메일함, 합성 샘플 5종)
- 발송 한도: 최근 24시간 실제 발송 수

**제외**
- 태그 없는 메일의 내용 기반 분류(L3) → P4
- 진행상황 요청 메일 → P5

## 2. 모드

| 조건 | 모드 |
|---|---|
| `SIMULATOR_MODE=true` | simulator |
| Gmail 주소, 앱 비밀번호, 수신 주소가 모두 있음 | gmail (SMTP 465 / IMAP 993) |
| 로컬에서 값이 없음 | simulator |
| 운영에서 값이 없음 | unconfigured (발송·수신 불가) |

## 3. DB (마이그레이션 `0002_mail`)

| 테이블 | 내용 |
|---|---|
| `mails` | direction(out/in), kind, status(sent/simulated/matched/unmatched/ignored), match_method, message_id(방향별 유일), 제목·본문·주소, simulated |
| `mail_attachments` | 첨부. 텍스트 파일(md 등)은 내용까지 저장 |
| `sim_inbox` | 가상 받은편지함 (주입된 메일, 처리 시각) |
| `app_state` | IMAP uidValidity, 마지막 UID, 마지막 확인 시각 |

## 4. 수신 규칙

**기록하는 메일:** 아래 중 하나에 해당하는 메일만 기록합니다(개인 메일이 섞이지 않도록).
- 제목에 `[AX_AIDD]` 태그가 있음
- 본문에 회신 양식 표식이 있음
- 회사 주소에서 보냄

**가져오는 범위:** 처음에는 최근 N일(기본 3일), 이후에는 마지막 UID 다음부터 가져옵니다. 처리를 마친 뒤에 위치를 저장합니다.

**단계 효과**

| 수신 메일 | 효과 |
|---|---|
| 수집 회신 | 1단계 완료, 2단계 진행중 |
| 진행상황 회신 | 6단계 완료 → **P5부터는 L6 해석에 성공해야 완료** (G-05) |
| 문서 전달 | 이력만 남김 (P4에서 등록) |

## 5. 알려진 문제

- **사내망 SSL 검사:** 사내망이 TLS를 가로채므로, Node가 Windows 인증서 저장소를 쓰도록 `npm run dev`와 `npm start`에 `--use-system-ca`를 넣었습니다. Gemini는 이 조치로 해결되었지만 Gmail은 여전히 실패합니다. 사용자가 사내 보안 정책을 확인하기로 했습니다.
